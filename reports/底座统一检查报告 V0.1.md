## 二、逐项检查结果

### 检查项 1：编号和等级是否统一（❌ 不统一）

三份文件各有一套编号规则，均未声明互相覆盖：

| 文件 | 编号示例 | 规则 |
| ---- | -------- | ---- |
| 基础知识卡模板 V0.1 | `文献-0001`、`原文-0001`、`概念-0001`、`主张-0001`、`假说-0001`、`决策-0001` | 中文类别前缀 + 四位流水号；并注明"第一阶段不建议设计过于复杂的编号体系" |
| 项目章程编写计划 V0.1 | `SRC-0001`、`PAS-0001`、`CON-0001` | 英文类别前缀 + 四位流水号 |
| 项目总体分期 | `SRC-ZHUANGZI-001`、`PAS-ZZ-XINZHAI-001`、`CON-QI-001`、`DEC-2026-001` | 英文类别 + 文献简称 + 三位流水号（决策带年份） |

证据等级规范 V0.1 的综合示例沿用了总体分期的 `CON-QI-001`、`DEC-2026-001` 风格。

**影响：** 卡片编号是跨卡引用、Obsidian 双向链接、Git 追溯的基础标识。三套并存会导致新卡片不知道该用哪套，且旧卡片无法统一引用。

**建议：** 采用模板 V0.1 原案（中文前缀 + 四位流水号）。理由：与模板"全部使用中文表达"原则一致；最简单，符合模板自述的"第一阶段不复杂"原则；模板已预留升级路径（后期可加文献简称，如 `原文-庄子-0001`），现阶段无升级必要。卡片之间的文献归属通过 frontmatter 的"所属文献编号"字段关联，不依赖编号本身。

### 检查项 2：卡片状态名称（❌ 不统一）

| 文件 | 状态体系 |
| ---- | -------- |
| 基础知识卡模板 V0.1 | 9 个中文状态：草稿、待核对、来源已核对、待解释审核、待综合审核、已审核、需要修订、不予采用、已归档 |
| 证据等级规范 V0.1 | 9 个英文状态：draft、source_pending、source_verified、interpretation_pending、review_pending、reviewed、revision_required、rejected、archived |
| 项目章程 V0.1 | 7 个状态的简化流程链：草稿 → 待核对 → 已核对来源 → 待同行审核 → 已审核 → 需修订 → 已归档 |

三个体系语义一一对应（证据规范英文状态与模板中文状态是同一套的两种语言），但**语言和数量不同**：模板比章程多出"待解释审核、待综合审核、不予采用"三个状态。

**建议：** 状态名称统一采用模板 V0.1 的 9 个中文状态（与人阅读习惯一致）；YAML 键统一用英文 `review_status`。证据规范 V0.1 的英文状态名降级为"技术对照名"保留在映射表中，章程 V0.2 修订时把 7 状态链改为 9 状态。

### 检查项 3：YAML 字段键语言（❌ 不统一）

| 文件 | YAML 写法 |
| ---- | --------- |
| 基础知识卡模板 V0.1 | 中文键：`文献编号:`、`传统署名:`、`文献可靠等级:` |
| 证据等级规范 V0.1 | 英文键：`text_reliability:`、`interpretation_level:`、`review_status:` |
| 项目总体分期 | 英文键：`id:`、`title:`、`source_id:` |

**建议：** 统一为 **键英文、值中文**。理由：YAML 键是给软件、脚本、Obsidian 属性和 VitePress 数据页使用的"技术名称"，按模板原则属于可保留英文的技术名；值（状态、类型等枚举）是给人阅读的内容，用中文。字母等级（T1-T5、I1-I5、E1-E5、M0-M4、R0-R5、C0-C4、S0-S4）本身即正式技术名称，保留。

**示例（统一后）：**

```yaml
id: 文献-0001
title: 道德经
text_reliability: T2
interpretation_level: I3
counterevidence_status: C1
risk_level: S0
review_status: 来源已核对
```

### 检查项 4：项目章程与安全边界是否冲突（✅ 无冲突）

逐节对照结果：

- 章程 9.3"暂不开放内容"与安全边界 5.1—5.5（呼吸、意守、静坐、饮食作息、意识体验）一致；
- 章程 9.4"风险停止原则"与安全边界 8（L1/L2/L3 异常分级）一致；
- 章程 10"AI 职责与限制"与安全边界 11（AI 安全规则）一致；
- 章程 14"隐私与人体研究边界"与安全边界 12（隐私与数据安全）一致；
- 章程 8"证据与可信度原则"与证据等级规范的多维评价原则一致（章程为摘要，规范为细则）。

**结论：** 章程是总纲，证据规范与安全边界是细则，三者层次清楚，无实质冲突。仅章程第 12 节的状态流程链与模板状态数不一致（见检查项 2）。

### 检查项 5：第一阶段研究范围是否一致（⚠️ 基本一致，一处遗漏）

- 章程 V0.1 第 15 节：第一阶段主题"静、虚、心、气、息、身之间的关系"，六部核心文献齐全；
- 一阶段计划：主线"静、虚、心、气、息、身"，六部文献齐全；
- 项目总体分期：核心主题写成"静、心、气、息、身之间是什么关系"——**遗漏了"虚"**；且 A 级精读书目为六部，与章程一致。

**建议：** 总体分期 V0.2 补正为六字主线。章程与一阶段计划口径一致，无需修改。

### 检查项 6：模板中是否存在重复字段（⚠️ 无实质重复，一处小缺口）

- 文献卡：YAML 24 字段与正文 16 节无重复；
- 原文卡："所属文献编号"与"所属文献"两个字段一个用于机器引用、一个用于人工阅读，建议保留；
- 概念卡：正文第 10 节"现代解释候选"有"当前等级"列，但 YAML 缺少对应的"现代证据等级"字段（解释等级 I、反证状态 C、风险等级 S 均有）。属轻微不一致，列入 V0.2 优化项；
- 各卡均有"修改记录"和"关联知识卡"，符合模板设计原则第 4 条（可追溯），无重复。

### 检查项 7：模板种类是否齐全（❌ 缺 3 种）

模板 V0.1 提供 6 种：文献卡、原文卡、概念卡、主张卡、假说卡、决策记录卡。

但项目其他文件要求了三种目前没有模板的卡片：

| 缺失模板 | 依据 |
| -------- | ---- |
| 争议卡（含"开放问题卡"） | 总体分期要求"10 张争议问题卡"、目录有 07-争议问题；章程第 5 节提到"开放问题卡" |
| 现代研究卡 | 一阶段计划第六步"建议新增两种资料卡"之一；目录有 08-现代研究 |
| 风险资料卡 | 一阶段计划第六步"建议新增两种资料卡"之二 |

**建议：** 模板清单扩充为 9 种，将模板 V0.1 单文件拆分为 `01-知识卡模板/` 目录下 9 个独立模板文件（模板 V0.2 任务，列入执行计划表步骤 1）。争议卡即"开放问题卡"，统一命名"争议卡"，避免两种叫法。

### 检查项 8：周期口径（⚠️ 不一致）

- 一阶段计划七步合计约 5—7 周（其中第四步"静专题"未给周期）；
- 总体分期第一期 12 周，且有逐周计划（第 1 周骨架 → 第 12 周网站发布）。

**建议：** 以 12 周为总预算，将一阶段计划七步对齐到总体分期周历（详见《阶段一执行计划表 V0.1》），多出周数作为缓冲和深化。

### 检查项 9：中英混排（⚠️ 少量）

模板明确要求"全部使用中文表达"，但：

- 总体分期卡片示例枚举值大量英文（`primary_text`、`early_daoist`、`philosophy`、`pending_review`、`active`）；
- 章程编写计划的文献卡示例有 `primary_or_secondary`。

**建议：** 内容枚举值一律中文化（文献类型：原始文献；所属传统：早期道家；文献体裁：哲学文献）。字母等级、YAML 键、软件名（Obsidian、GitHub、Markdown、VitePress）作为技术名称保留。总体分期与章程编写计划在 V0.2 修订时清理。

### 检查项 10：其他发现

1. **项目简介中的证据等级表已过时**：简介第五节使用 A/B/C/D/E/X 单一等级表，证据规范 V0.1 已升级为多维体系（T/I/E/M/R/C/S）。简介应在 V0.2 修订时删除旧表，指向证据规范。该表此前从未在正式文件中启用，无回溯影响。
2. **目录结构三套**：一阶段计划（中文 00-11）、总体分期（英文 knowledge/ 等）、章程编写计划（英文 templates/ + knowledge/）。已按"模板全部中文表达"原则采用中文目录，并补充了风险资料卡目录（09-风险资料卡，原 11-待处理资料顺延为 12）。
3. **private/ 目录**：总体分期要求 `private/` 不提交 GitHub。目录已建，需加入 .gitignore。
4. **本机工具情况**：未检测到 Obsidian、Zotero 的标准安装路径，工具安装确认列入执行计划表步骤 2。
