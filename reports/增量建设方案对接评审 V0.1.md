# 问道志增量建设方案对接评审 V0.1

**日期：** 2026-08-03
**评审对象：** 《问道志增量建设方案》（问题地图 / 概念辨析 / 争议多解 / 修持分级 / 来源溯源 / 社区观察 / AI 审校台 + 原有资料补充 + 目录调整建议）
**评审任务：** 方案每项与现有知识体系（证据等级规范、安全边界、12 种模板、17 个目录、三类模块、工作包机制）逐一对照，判定「新增 / 映射现有 / 需决策 / 不采用」，给出与现有工作流兼容的落地批次。
**评审结论先行：** 方案方向正确、多数值得吸收，但约半数条目与现有体系重叠或编号冲突，**不能直接照搬**；需映射、重编号后分三批落地。

---

## 一、总体判断

方案的内核（外层用户问题入口 + 中间辨析争议结构 + 底层来源可信度与安全控制）与项目现有原则一致，特别是：

- "社区用来发现问题，不直接充当权威答案" → 与现有「当代传播资料卡 / 参考网站 / 社区观察分层」原则一致；
- "AI 是研究助手，不是裁判" → 与现有「AI 输出一律待人工核对」一致；
- "修持内容分级、风险隔离" → 与现有《安全边界》S0—S4 分级一致。

因此方案不是另起炉灶，而是**现有体系的三类扩展**：

1. **新增能力**：问题地图（入口层）、概念辨析卡（辨析层）、社区观察层、AI 审校台、多学习路线；
2. **映射现有**：来源可信等级 → 现有证据等级（T/I/E/M/R/C/S 已覆盖）；修持分级 → 现有安全边界 S 级；争议多解 → 现有争议卡；
3. **冲突需重编号**：方案建议目录 06—12 与现有 06—12 全部编号冲突。

## 三、落地批次建议（与工作包机制兼容）

> 当前 TOPIC-001 处于「进行中（阶段 0 范围冻结）」。本方案属项目结构层建设，参照「结构拆分（三类模块）」先例，可并行作为独立批次执行，**不进入研究内容**；或等 TOPIC-001 验收后执行。由项目负责人定。

### 批次 A（规则层，底层工程——方案"第一阶段"对应项）

1. 新建 18-问题地图/、19-概念辨析/、20-社区观察/ 三个目录（含 README 规则）；
2. 新建问题卡、辨析卡、社区观察卡、AI 审校记录卡四张模板；
3. 扩展争议卡模板（观点三/争议形成时间/项目采用表达）；
4. 扩展风险资料卡模板（是否适合自学/是否需要教师/前置条件）；
5. 扩展文献卡模板（版本信息字段）、概念卡模板（历史时期字段）；
6. 建《来源类型与可信展示规范》（映射现有证据等级，不建第二套等级）；
7. 基础规范 V0.5：编号体系/目录/模板清单更新。

### 批次 B（试点内容层，方案"第二阶段"）

1. 问题地图首批 10 问（方案示例问题），每问连接现有卡；
2. 辨析卡首批 5 组（道家与道教、无为与不作为、坐忘与冥想、内丹与气功、自然与自然界）；
3. 修持分级映射表（方案 0—4 级 ↔ 安全边界 S0—S4 对照，用于公开页展示）。

### 批次 C（入口与机制层，方案"第三—五阶段"）

1. website 四条学习路线入口；
2. 社区观察首批样本（记录 Reddit/知乎高频问题，标记观察层身份）；
3. AI 审校工作流并入现有审查流程（审校记录卡接入反方审查 11 项）。
