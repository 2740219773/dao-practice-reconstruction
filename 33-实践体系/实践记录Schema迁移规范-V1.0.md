# 问道志实践记录 Schema 迁移规范 V1.0

## 一、为什么现在就要定义迁移

当前实践记录已经使用：

```text
wendaozhi.practice.records.v1
schemaVersion: 1
```

只要真实用户开始连续记录，后续新增字段、调整枚举或更换存储结构就会遇到一个问题：

> 新代码如何读取旧记录，又如何避免把未来版本的数据错误覆盖？

因此在 schema v1 仍处于早期阶段时先建立迁移规则，比等到 v2 发布后再补救更稳妥。

## 二、当前不升级 schema

本规范建立迁移机制，但当前仍保持：

```text
SCHEMA_VERSION = 1
```

原因：

- 当前记录字段仍足够支撑 7天/30天/阶段复盘；
- 不为了“有版本升级”而制造无意义迁移；
- 先验证迁移框架，再在真正需要字段变化时发布 v2。

## 三、迁移必须逐版本进行

未来如果当前版本是 v3，而导入数据是 v1，不允许：

```text
v1 → 直接猜成 v3
```

必须：

```text
v1
↓ 明确 migration 1→2
v2
↓ 明确 migration 2→3
v3
```

每一步都有独立、可测试的转换函数。

## 四、禁止隐式猜测

如果缺少某一步迁移函数：

```text
v1 → v2 缺失
```

系统必须停止，并提示：

> 缺少显式迁移规则，原数据不会被覆盖。

不得通过给缺失字段填默认值的方式“碰碰运气”继续升级。

## 五、未来版本数据禁止降级覆盖

如果当前程序只支持 v1，却读取到：

```text
schemaVersion: 2
```

系统必须拒绝自动加载/覆盖，并明确：

> 这是更高版本数据，当前版本不支持自动降级。

原因：旧程序并不知道新字段的语义，继续写回很可能造成不可逆数据丢失。

## 六、迁移与数据清洗分开

迁移回答：

> 数据结构如何从一个 schema 变成下一个 schema？

规范化回答：

> 当前 schema 下，这条记录是否仍然合法？

流程：

```text
解析 JSON
↓
识别 sourceVersion
↓
逐版本迁移
↓
到达 currentVersion
↓
normalizeRecord 规范化
↓
过滤非法记录
↓
返回迁移报告
```

不能把迁移和“偷偷删掉不认识的字段”混在一起。

## 七、原数据保护

迁移失败时：

- 不覆盖 localStorage；
- 不自动清空；
- 不自动降级；
- 不把失败解释成“没有记录”。

UI 应提示用户先导出原始数据或更新到支持该 schema 的版本。

## 八、迁移结果必须返回元信息

迁移模块至少返回：

```text
ok
code
sourceVersion
targetVersion
migrated
records
rejected
error
```

这样 UI 可以区分：

- 没有数据；
- JSON 已损坏；
- 数据来自未来版本；
- 缺少迁移规则；
- 成功迁移但有部分非法记录被拒绝。

## 九、迁移函数要求

每个 `vN → vN+1` 函数必须：

- 纯函数；
- 不访问 localStorage；
- 不发网络请求；
- 不修改输入对象；
- 输出明确 `schemaVersion: N+1`；
- 有自动化测试；
- 在版本说明中记录字段变化。

## 十、存储键策略

当前键：

```text
wendaozhi.practice.records.v1
```

未来若升级 v2，可以选择：

```text
wendaozhi.practice.records.v2
```

推荐迁移顺序：

1. 先读取目标版本键；
2. 若不存在，再查找已知旧版本键；
3. 用明确迁移规则生成 v2 数据；
4. 在写入新键前保留旧键；
5. 只有用户明确确认或经过稳定版本周期后，才考虑清理旧键。

当前 v1 不执行这一步，只预先定义规则。

## 十一、导入文件规则

JSON 导入同样必须经过 schema 识别和迁移。

不能仅因为文件扩展名是 `.json` 就直接合并。

未来支持旧版本导入时：

```text
文件
↓
版本识别
↓
迁移
↓
规范化
↓
同ID合并
```

未来版本文件继续拒绝降级导入。

## 十二、当前实现

代码：

`website/docs/.vitepress/theme/practice/practice-migrations.mjs`

提供：

- `migrateEnvelope`；
- `parseAndMigrateStored`；
- `migrationRegistry`。

当前没有 `1→2` 迁移函数，因为 v2 schema 尚未存在。

## 十三、验收标准

- [ ] 当前 v1 可以无迁移读取；
- [ ] 非法 JSON 不覆盖原数据；
- [ ] 未来版本拒绝自动降级；
- [ ] 缺失迁移步骤时明确失败；
- [ ] 可注册并测试逐版本迁移函数；
- [ ] 迁移失败不等于“无记录”；
- [ ] 迁移与 normalize 分开；
- [ ] 第一版无网络依赖；
- [ ] 真正升级 v2 前必须先补 `1→2` 测试与变更说明。
