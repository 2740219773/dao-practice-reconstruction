# 问道志实践体系

## 一、定位

本目录承接问道志从“可靠知识研究”向“低风险、可记录、可复盘、可长期纠偏的基础实践”扩展后的实践层。

实践层不是把古籍改写成教程，也不是把知识图谱中的 `method.*` 节点直接变成操作步骤。它是一套现代教学、记录与复盘系统：传统材料提供历史与思想背景，现代安全资料提供边界，项目据此设计可停止、可观察、可回退的基础单元。

核心原则：

> 有传统依据，不等于古法复原；能形成现代练习，不等于传统原文就是练习说明。

## 二、四层必须分开

实践体系中的内容必须区分：

1. 历史传统层：经典原文、历史方法、后世传统解释；
2. 现代教学层：问道志为现代低风险场景设计的教学单元；
3. 个人观察层：个人当次体验、异常与变化；
4. 现代证据层：医学、心理学、运动科学等现代研究。

禁止：

```text
古籍一句话 → 直接改写成现代功法步骤
个人一次体验 → 传统理论被证明
现代生理指标 → “气”等传统概念被科学证实
```

## 三、实践开放级别

| access_level | 中文定位 | 处理方式 |
| --- | --- | --- |
| `knowledge_only` | 知识了解 | 只学习，不给操作步骤 |
| `basic_low_risk` | 低风险基础实践 | 可提供短时、自然、可停止的基础教学单元 |
| `guided` | 建议指导 | 需要可靠指导者或专业意见后再进行 |
| `teacher_required` | 需可靠教师/传承 | 不自动生成自学教程 |
| `research_only` | 仅研究记录 | 只做历史、理论、风险研究 |
| `prohibited` | 禁止执行 | 只记录存在和风险，不展开操作 |

开放级别与 `S0—S4` 风险等级是两套不同字段。

## 四、当前基础路线

当前仍只开放八张 `S1` 低风险现代教学单元：

1. 准备与安全检查；
2. 调身与舒适姿势；
3. 身体接触觉察；
4. 自然察息；
5. 注意返回与收心基础；
6. 短时基础安坐；
7. 轻柔动静转换；
8. 日用觉察。

它们不是“道家统一八步功法”，只是问道志的现代基础能力教学顺序。该顺序不进入 V3 历史图谱。

所有第一批卡继续：

```text
type: practice
practice_kind: modern_teaching_unit
historical_equivalence: false
risk_level: S1
activity_class: B
access_level: basic_low_risk
status: review
```

## 六、V2.7：首轮7天真实试运行

当前实践产品处于：

**V2.7 首轮真实试运行与产品减法。**

规范：

- `7天首轮试运行方案-V1.0.md`；
- `记录模板/7天试运行观察.md`。

首轮目的不是验证修炼效果，而是验证：

- 今日入口是否减少决策；
- 每日记录是否过重；
- 哪些字段真正有信息价值；
- 安全信息是否在需要时足够醒目；
- 7天复盘是否先给出有用结论；
- 数字和 AI 材料是否真的会被使用；
- 哪些词仍容易被理解成打卡、升级或等级；
- 下一版最应该删什么、折叠什么、改写什么。

首轮不要求全勤，不按天推进实践卡，不把连续天数或总分钟数作为晋级条件。

## 七、V2.7 四轮产品减法

### 第一轮：产品观察退出主流程

`7天产品观察` 默认折叠，明确：

> 可选 · 约20秒 · 只记录系统是否好用

没有使用工作台时不再要求填写无意义的耗时、入口和字段摩擦。

### 第二轮：今日首屏退出低价值字段

- “阶段方向”退出今日卡，只在30天复盘出现；
- 情绪默认 `not_observed`，不再虚构“稳定”；
- 下次决定默认 `not_decided`，不再替用户写“继续”；
- 不为了界面减法升级 schema。

### 第三轮：异常与安全渐进展开

正常记录只显示：

> 异常与安全（没有则跳过）

出现草稿安全提醒、已勾选问题或已选择安全分流时再展开完整内容。

系统不会自动替用户设置黄色/红色，也不会做医学诊断。

“今天决定不练”保存时清理本次练习观察、问题、安全分流和后续决定，避免未发生的练习携带旧异常。

### 第四轮：7天复盘按信息价值排序

最近7天默认顺序：

```text
规则型复盘
↓
重复问题
↓
查看7天数据细节（折叠）
↓
AI复盘材料（可选，折叠）
```

边界：

- 规则提醒始终可见；
- 真实重复问题始终可见；
- 没有重复问题时压缩为轻提示；
- 六项统计没有删除，只是不抢占首屏；
- AI 材料没有删除，只在需要时展开；
- 减负不得弱化安全语义。

第四轮测试还发现并修正：单次明确黄色事件不能被“没有触发重复安全规则”的稳定提示覆盖。现在单次黄色也会生成 `yellow_event` 提醒，但不等于自动医学判断。

## 八、修持记录与产品观察分离

### 修持记录

```text
wendaozhi.practice.records.v1
schemaVersion: 1
```

用于：

- 每日事实记录；
- 最近7天规则复盘；
- 最近30天记录支持状态；
- 黄色/红色安全记录；
- AI 统计摘要。

### 产品观察

```text
wendaozhi.practice.trial.v1
schemaVersion: 1
```

用于记录产品摩擦：

- 总体操作耗时；
- 主要入口；
- 难选字段；
- 低价值字段；
- “系统在催升级/打卡”的感觉；
- 一句话产品备注。

产品观察明确：

- 不进入修持 schema；
- 不参与最近7天/30天阶段判断；
- 不生成修为分或完成率；
- 不改变实践记录数量；
- 清空产品观察不删除修持记录；
- 不自动上传网络。

## 九、知识层与实践层的关系

实践卡可以链接：

- `concept.*`：传统概念；
- `method.*`：历史方法研究节点；
- `classic.*`：经典；
- `policy.*`：安全规则。

实践关系当前只在实践层使用：

- `prerequisite_for`；
- `contextualized_by`；
- `not_equivalent_to`；
- `safety_constrained_by`；
- `reviewed_by`。

典型边界：

```text
自然察息 ≠ 吐纳 / 服气
注意返回基础 ≠ 《坐忘论》完整收心体系
短时基础安坐 ≠ 坐忘 / 内丹筑基
轻柔动静转换 ≠ 古代导引套路复原
```

## 十一、自动化基线

当前核心修持模块：

```text
practice-model.mjs
practice-migrations.mjs
practice-stats.mjs
practice-safety.mjs
practice-ai.mjs
practice-stage.mjs
practice-safety-reduction.ts
practice-review-reduction.ts
```

独立产品观察模块：

```text
practice-trial.mjs
PracticeTrial.vue
```

`npm run test:practice` 当前运行 **39 个**场景，覆盖：

- 修持数据与最小字段；
- 不练记录；
- 7天统计与安全规则；
- 单次黄色 `yellow_event`；
- 30天阶段复盘；
- AI 摘要边界；
- schema 迁移保护；
- 产品观察隔离与版本保护。

当前顶层有四条 Chromium CI 入口：

```text
npm run test:e2e:practice
npm run test:e2e:daily
npm run test:e2e:trial
npm run test:e2e:theme
```

其中 `test:e2e:daily` 内部串行：

```text
今日入口 / 双向导航
↓
今日首屏低价值字段减法
↓
异常与安全渐进展开
↓
7天复盘信息层级减法
```

GitHub Actions 还会等待 Cloudflare Pages `/build-info.json` 追上当前提交，再做真实线上验证。
