# 问道志知识—实践关系规范 V1.0

## 一、为什么单独建一套关系

V3 知识图谱主要表达历史实体、文本来源、概念关系、人物与传统等知识关系。

实践体系则包含问道志自己设计的现代教学顺序。

二者不能共用一套没有类型区分的箭头，否则很容易把：

```text
问道志建议先做 A 再做 B
```

误读成：

```text
古代传统认为 A 历史上发展成 B
```

因此第一阶段把实践关系独立维护，不直接注入 V3 历史图谱。

## 二、允许的实践关系

### `prerequisite_for`

表示问道志现代教学依赖。

例如：

```text
准备与安全检查 prerequisite_for 调身与舒适姿势
```

含义只是“本项目建议先建立前项能力”。

不表示历史次第、宗派师承或经典规定。

### `contextualized_by`

表示某张现代实践卡可由某个传统概念、历史方法或经典材料提供背景理解。

例如：

```text
自然察息 contextualized_by 息
```

只表示研究背景关联。

### `not_equivalent_to`

显式声明现代教学单元不等同于某个历史方法。

例如：

```text
自然察息 not_equivalent_to 吐纳
自然察息 not_equivalent_to 服气
短时基础安坐 not_equivalent_to 坐忘
```

这是实践层非常重要的“防误读关系”。

### `safety_constrained_by`

表示实践卡受某一安全规范约束。

例如：

```text
自然察息 safety_constrained_by 安全边界 V0.2
```

### `reviewed_by`

未来用于表示某实践单元经过指定审核流程或版本审核。

第一版暂不自动生成该关系，等正式人工审核机制形成后再使用。

## 三、禁止在实践关系中直接使用的历史关系

实践关系文件禁止使用：

- `authored`；
- `founded`；
- `develops`；
- `influences`；
- `traditional_attribution`；
- `belongs_to`（用于历史分类时）；
- 任何未经限定的“传承”“源自”。

如果未来确实需要表达历史事实，应回到 V3 知识层，并使用历史来源支持。

## 四、实践关系数据结构

第一版机器数据使用 JSON，避免给网站构建额外引入 YAML 解析依赖。

```json
{
  "version": "1.0",
  "scope": "practice_layer_only",
  "relations": [
    {
      "id": "practice-rel-001",
      "source": "practice.basic.precheck",
      "target": "practice.basic.posture",
      "relation": "prerequisite_for",
      "scope": "问道志基础能力教学顺序",
      "sourceRefs": ["source.project.practice.design.v02"]
    }
  ]
}
```

## 五、关系方向

`prerequisite_for`：有方向。

```text
A prerequisite_for B
```

表示 B 以 A 为项目教学前置。

`contextualized_by`：有方向。

```text
practice contextualized_by knowledge-node
```

不自动生成反向边。

`not_equivalent_to`：语义上可理解为不等同，但机器数据仍从 `practice` 指向知识节点维护一条即可。

`safety_constrained_by`：从实践指向规范。

## 六、当前八张基础卡的关系边界

### 自然察息

允许：

```text
contextualized_by concept.xi
not_equivalent_to method.tuna
not_equivalent_to method.fuqi
```

不允许：

```text
concept.xi -> method.tuna -> practice.basic.natural_breath
```

来暗示历史演变链。

### 注意返回与收心基础

允许：

```text
contextualized_by concept.xin
contextualized_by method.zuowang
not_equivalent_to method.zuowang
```

这里同时“有关联”和“不等同”并不冲突：前者说明理解背景，后者说明现代教学单元不是历史体系本身。

### 短时基础安坐

允许：

```text
contextualized_by method.jingzuo
not_equivalent_to method.zuowang
not_equivalent_to method.neidan
```

### 轻柔动静转换

允许：

```text
contextualized_by method.daoyin
not_equivalent_to method.daoyin
```

## 七、实践路线箭头规则

网站上的：

```text
01 → 02 → 03 → ... → 08
```

必须在视觉或说明中明确：

> “问道志现代基础教学建议顺序”

不得使用“传承路线”“道家修炼正统次第”等标题。

## 八、未来进入统一图谱的前置条件

只有同时完成以下工作后，实践层才考虑进入统一图谱展示：

1. V3 节点模型增加 `practice_unit` 或独立 layer；
2. 图谱 UI 能明显区分历史知识边和现代教学边；
3. 关系类型支持本规范四种实践关系；
4. 默认筛选不会把现代路线和历史关系混在一起；
5. 用户能一眼识别“这是项目设计，不是古代史实”；
6. CI 能阻止实践边使用历史因果/师承关系。

在此之前，实践关系只维护在 `33-实践体系/实践关系-v1.json`。
