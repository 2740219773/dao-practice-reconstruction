# 基础实践体系第一轮产品审查

日期：2026-08-12

## 一、审查范围

本轮不是重新讨论八张基础卡是否“像传统功法”，而是从产品可用性、数据真实性、风险边界和后续扩展四个角度检查 PRACTICE-001 / PRACTICE-002 第一版。

审查对象：

- 八张 `practice.basic.*` 基础实践卡；
- 实践首页；
- 本地记录与 7 天复盘工具；
- JSON 导入导出；
- AI 复盘材料；
- 实践关系模型；
- 实践体系独立 CI 质量门。

## 二、已通过项

### 1. 历史知识与现代实践分层

通过。

第一批实践卡统一：

```text
practice_kind: modern_teaching_unit
historical_equivalence: false
```

并通过 `not_equivalent_to` 关系显式防止：

- 自然察息 = 吐纳/服气；
- 注意返回 = 坐忘体系；
- 短时安坐 = 坐忘/内丹；
- 轻柔动静转换 = 古代导引套路。

### 2. 风险开放边界

通过。

第一批公开实践仍限制在：

```text
S1 + B 类 + basic_low_risk
```

主动调息、闭气、胎息、强意守、长时禁动、服气、内丹火候/周天、辟谷、丹药等没有进入自动教程。

### 3. 本地优先隐私

通过。

当前交互组件：

- 使用版本化 `localStorage` 键；
- 不包含 `fetch` / `XMLHttpRequest` / `axios` 自动上传；
- 只有用户主动导出 JSON 或复制 AI 复盘材料时数据才离开页面；
- 支持用户删除单条、清空全部本机记录。

### 4. 复盘不制造“境界分”

通过。

自动汇总只包含：

- 次数；
- 实际时长；
- 重复问题；
- 黄色/红色事件；
- 主要实践卡。

不生成修为分、静心指数、气感指数或连续打卡等级。

### 5. 红色事件优先级

通过。

有红色事件时，自动规则停止推荐加量和高级练法，只提示停止相关实践并按安全边界处理。

### 6. AI 复盘边界

通过。

复制给 AI 的材料自带约束：

- 不补造经历；
- 不诊断；
- 不判断气、经络、丹田或境界；
- 不生成 S2—S4 教程；
- 红色信号优先；
- 无异常也不自动加时。

## 三、本轮发现并修正的问题

### 问题 1：日志表单不应阻止“超时事实”被记录

原设计把实践卡建议上限直接作为表单 `max`，并在超时后拒绝保存。

这会造成数据偏差：

> 用户实际练了 15 分钟，但因为建议上限是 10 分钟，系统反而不让记录 15 分钟。

已改为：

- 实际时长可如实记录到 120 分钟；
- 页面仍显示该卡“当前审查上限”；
- 超过上限时保存成功，同时提示“事实记录不代表下次应继续超时”。

原则：

```text
记录真实性 > 训练合规性美化
```

系统应该记录发生了什么，而不是只允许记录“正确行为”。

### 问题 2：数据模型有 `emotionState`，但第一版 UI 没有输入控件

这会导致每条记录都默认写成 `stable`，形成伪数据。

已增加“情绪状态”字段：

- 稳定；
- 有波动但可接受；
- 明显干扰；
- 因此停止。

### 问题 3：导入数据需要限制未知实践 ID

原第一版导入只检查 `id/date/practiceId` 是否存在，但没有确认 `practiceId` 是当前支持的八张基础卡。

已改为：

- schema v1 只导入已知 `practice.basic.*` ID；
- 未知实践 ID 不自动映射、不执行、不生成建议；
- 未来增加新卡时通过数据版本或兼容迁移处理。

### 问题 4：实践质量门不应依赖 `graph:check` 的副产物

首次 CI 中实践检查尝试读取 `data/nodes.json`，但现有 `graph:check --check` 按设计只校验、不写 `data/`，导致质量门失败。

已修正为：

- 直接扫描 `23-*` 至 `32-*` 的 V3 源 Markdown `id`；
- 直接验证实践关系的 `concept.* / method.* / classic.*` 端点；
- 不依赖 `data/` 是否已经生成。

修正后 CI 通过。

## 四、当前仍保留的限制

### 1. 没有云同步

这是当前有意的产品限制，不是缺陷。个人实践数据优先保持本地。

### 2. 没有内置远程 AI

当前只生成可复制的复盘材料，不自动发送记录。等隐私、权限和输出审计机制建立后再考虑内置。

### 3. 没有自动判定黄色/红色

第一版由用户依据安全页自行标记。

原因：

- 同一个“头晕”可以有不同严重程度；
- 自动判定容易被误解成医学分诊；
- 当前项目没有足够临床上下文做自动判断。

后续可以做“安全问题引导式问卷”，但必须避免诊断语气。

### 4. 没有自动升级阶段

继续保持。记录工具只能提示“保持、缩短、回退、暂停”，不授予“已完成筑基/已进入某境界”等资格。

## 五、下一轮优先级

### P0：真实使用试跑

用实际浏览器完成至少以下场景：

1. 正常记录一次；
2. 记录“决定不练”；
3. 记录超过卡片审查上限的真实时长；
4. 连续两次记录“主动控制呼吸”，确认 7 天复盘触发对应提醒；
5. 记录黄色事件；
6. 记录红色事件，确认页面不再推荐加量；
7. 导出 JSON 后重新导入；
8. 删除单条与清空数据；
9. 移动端表单可用性；
10. 深色/浅色主题下可读性。

### P1：记录数据模型解耦

当前记录逻辑仍集中在 Vue 组件。试跑稳定后，应拆出独立纯函数模块：

- schema 校验；
- 数据迁移；
- 周统计；
- 安全规则；
- AI 摘要生成。

这样可以单元测试，不把所有逻辑绑死在 UI。

### P1：阶段复盘交互

现网页只实现“最近 7 天”。下一步可增加 30 天/阶段视图，但仍不生成总分。

### P2：实践—知识联合展示

等实践关系模型稳定后，在实践详情页显示：

- “传统背景”；
- “明确不等同”；
- “安全约束”；
- “继续学习”。

但不要把这些边混进历史知识图谱默认视图。

## 六、结论

第一轮产品审查结论：

**可以继续试运行，但仍处于 `review`，暂不把八张基础卡标记为 `published`。**

当前最有价值的不是继续增加第 9、第 10 张练习，而是让已有 8 张卡经过真实记录、复盘、异常和数据恢复场景的使用验证。
