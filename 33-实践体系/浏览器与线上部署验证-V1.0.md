# 问道志浏览器与线上部署验证 V1.0

更新时间：2026-08-12

## 一、目的

问道志网站当前通过 GitHub 更新后自动部署到 Cloudflare Pages：

`https://wendaozhi.pages.dev/`

因此实践体系不能只验证“源码能编译”，还需要区分三层：

```text
纯规则测试
↓
真实 Chromium 本地端到端
↓
Cloudflare Pages 线上部署验证
```

三层各自解决不同问题。

## 二、真实 Chromium 端到端

脚本：

`website/scripts/e2e-practice-browser.mjs`

命令：

```text
npm run test:e2e:practice
```

GitHub Actions 会在网站构建完成后启动真实无头 Chromium，并对构建产物进行实际交互。

当前已自动验证：

1. `/practice/` 实际加载；
2. “每日记录 / 最近7天 / 30天与阶段 / 数据管理”四个标签存在；
3. 通过真实表单事件保存一条实践记录；
4. 记录实际写入 `localStorage`；
5. 页面刷新后记录仍保留；
6. 数据管理页能看到刷新后的记录；
7. 记录不足时 30 天阶段页输出“继续当前阶段，先补足记录”；
8. 不会因少量记录自动分流或晋级；
9. 通过真实表单保存红色事件；
10. 红色事件出现后阶段页优先输出“因安全原因暂停并处理异常”；
11. 红色事件页面提供安全边界入口；
12. 390px 窄屏下实践工作台不明显横向溢出；
13. 窄屏标签栏允许横向滚动。

这已经比纯单元测试更接近真实用户行为，但仍属于自动化 Chromium 测试。

## 三、端到端脚本的运行保护

首版 Chromium 脚本曾出现子进程未正常结束，CI 长时间停留在该步骤。

后续已增加：

- 真实 Chrome/Chromium 可执行文件自动发现；
- DevTools 协议连接超时；
- 页面条件等待超时；
- 总体硬超时；
- Chrome 与本地预览进程强制收尾；
- 成功/失败后显式退出进程。

因此端到端测试本身也必须具备“可失败、可结束”的工程边界。

## 四、Cloudflare Pages 线上部署验证

脚本：

`website/scripts/smoke-production.mjs`

默认线上地址：

```text
https://wendaozhi.pages.dev
```

main 分支 push 后，GitHub Actions 会：

```text
读取 github.sha
↓
轮询线上 /build-info.json
↓
等待 Cloudflare Pages 的 commit 追上当前提交
↓
再开始线上页面检查
```

当前等待策略：

```text
最多 36 次
每次间隔 10 秒
```

这样不会因为 GitHub Actions 已经开始、Cloudflare Pages 还在构建而立即误判失败。

## 六、第一次线上验证实际发现的问题

第一次正式把生产站纳入 CI 后：

```text
Cloudflare Pages 部署：成功
目标提交追踪：成功
自然察息 .html URL：返回 308
```

这不是页面不可用，而是 Cloudflare 对：

```text
/practice/card/natural-breath.html
```

进行了规范化重定向。

项目实际链接使用：

```text
/practice/card/natural-breath
```

因此线上冒烟测试已调整为：

- 规范 URL 必须返回 200；
- `.html` URL 必须返回 301/302/307/308，并指向规范 URL。

这体现一个原则：

> 生产环境测试应验证用户实际访问路径和平台真实路由规则，而不是把本地文件名当成线上 URL。

## 七、CI 并发处理

网站工作流增加：

```text
concurrency:
  group: website-${{ github.ref }}
  cancel-in-progress: true
```

原因是 GitHub 连续提交时，旧工作流不应该继续等待一个已经被后续提交替代的 Pages 部署。

只有当前最新分支提交需要完成“本地构建 → Chromium → Pages 线上验证”的完整链路。

## 八、当前自动验证与人工验证的边界

### 已自动验证

- Chrome/Chromium 实际页面加载；
- 表单保存；
- localStorage 刷新保留；
- 数据管理展示；
- 30天阶段阻断；
- 红色事件安全暂停；
- 390px 窄屏基本溢出；
- Cloudflare Pages 自动部署追踪；
- 线上主要页面状态；
- 生产 URL 规范化与旧路径重定向。

### 仍需人工或进一步自动化

- “今天决定不练”的完整真实点击体验；
- 黄色事件填写是否容易理解；
- JSON 文件真实下载、选择文件和重新导入的浏览器权限体验；
- 剪贴板权限拒绝后的体验；
- 删除与清空确认框体验；
- 深色/浅色主题视觉检查；
- Edge；
- Safari；
- iOS Safari / Android Chrome；
- 键盘导航与无障碍；
- 真实连续使用 7 天、30 天后的信息密度；
- 用户是否会误解“记录支持稳定”为修炼认证。

## 九、当前结论

截至 2026-08-12，问道志已经形成：

```text
规则级自动测试
+
真实 Chromium 端到端
+
Cloudflare Pages 当前提交线上冒烟
```

因此后续“真实浏览器试跑”不再从零开始。

下一步重点应转向：

1. 多浏览器与移动端实际体验；
2. 文件/剪贴板/确认框等浏览器权限操作；
3. 长期真实记录后的产品可读性；
4. 实践工作台体验减负；
5. 仍然保持八张基础实践卡 `status: review`，不因自动化全绿直接改为正式发布。
