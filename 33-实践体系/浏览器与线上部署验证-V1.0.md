# 问道志浏览器与线上部署验证 V1.1

更新时间：2026-08-12

## 一、验证分层

问道志网站由 GitHub main 更新后自动部署到：

`https://wendaozhi.pages.dev/`

当前质量链分为四层：

```text
纯规则/数据测试
↓
实践工作台真实 Chromium E2E
↓
日读/夜读真实 Chromium E2E
↓
Cloudflare Pages 当前提交线上验证
```

单元测试解决“规则是否正确”；浏览器测试解决“用户实际点击后是否正确”；线上冒烟解决“自动部署后的真实站点是否对应当前提交”。

脚本：`website/scripts/e2e-practice-browser.mjs`

命令：

```text
npm run test:e2e:practice
```

3. ArrowRight 键盘切换标签并同步 `aria-selected`；
4. 普通实践记录通过真实表单保存；
5. 数据实际写入 `localStorage`；
6. 页面刷新后数据保留；
7. “今天决定不练”后无关字段隐藏；
8. 不练记录最终时长为0且明确“不计失败”；
9. JSON 导出实际生成可解析 schema v1 数据；
10. JSON 导入使用真实 `File + DataTransfer + change` 事件；
11. 导入后仍经过现有 merge/schema 边界；
12. 单条删除取消确认时不删除；
13. 单条删除确认后才删除；
14. 清空全部取消确认时不清空；

## 三、阅读主题 Chromium E2E

脚本：`website/scripts/e2e-theme-browser.mjs`

命令：

```text
npm run test:e2e:theme
```

阅读主题不是普通纯黑/纯白：

```text
日读：暖宣纸 + 深墨
夜读：深纸 + 浅墨 + 克制朱砂
```

当前验证：

- 用户没有存储偏好时可参考系统深浅主题；
- 测试固定从日读开始；
- 点击后 `data-wdz-theme` 从 `light` 切到 `dark`；
- 主要纸色与墨色的计算样式确实发生变化；
- `aria-pressed` 与按钮提示同步；
- 用户选择写入 `wendaozhi.reading.theme`；
- 页面刷新后仍恢复夜读；
- 390px 移动端仍显示可点击主题按钮；
- 可以正常切回日读并保存。

## 四、为什么主题测试单独拆分

主题功能属于全站阅读体验，不属于实践数据业务。

单独测试可以避免：

```text
实践表单回归失败
```

和：

```text
主题视觉/持久化失败
```

混成同一个大脚本，也便于未来把夜读扩展到截图比对或更多页面。

## 五、浏览器脚本运行保护

两条 Chromium 脚本都必须：

- 自动发现 Chrome/Chromium；
- 有 DevTools 连接等待；
- 有页面条件等待；
- 有总体硬超时；
- 无论成功失败都强制收尾 Chrome 与本地预览进程。

浏览器测试本身也必须“可失败、可结束”，不能因为自动化脚本卡住而无限占用 CI。

```text

```

## 八、CI并发

```text
concurrency:
  group: website-${{ github.ref }}
  cancel-in-progress: true
```

连续提交时，只让最新提交继续等待 Pages 部署，避免旧提交验证一个已经不会再成为线上最新版本的 SHA。

## 十、结论

当前工程已经从：

```text
“代码能构建”
```

推进到：

```text
规则自动测试
+ 实践真实Chromium
+ 阅读主题真实Chromium
+ Cloudflare当前提交线上冒烟
```

八张基础实践卡仍保持 `status: review`。自动化证明产品行为不容易回归，不证明某种传统修炼方法已经被验证有效。
