# 问道志实践工作台可访问性验证 V1.0

更新时间：2026-08-14

## 一、目的

本文件只说明问道志实践工作台当前已经自动验证的可访问性工程边界。

它不等于：

- 已完成 WCAG 全量审计；
- 已通过 VoiceOver / TalkBack / NVDA / JAWS 真机验证；
- 已证明 Safari、iOS Safari、Android Chrome 行为完全一致。

当前自动化目标是：先消除可以在 Chromium 中稳定发现的键盘、语义和触控基础问题，再把真实辅助技术与多浏览器差异留给真机验证。

---

## 二、当前增强层

实现：

- `website/docs/.vitepress/theme/practice/practice-accessibility.ts`
- `website/docs/.vitepress/theme/styles/practice-accessibility.css`

原则：

> 不改修持 schema，不增加练法，不改变7天/30天判断，只补现有界面的可访问性语义与操作连续性。

### 2.1 标签页关系

四个工作台分页继续使用原有 `role="tablist" / role="tab"`，并补齐：

```text
Tab
├─ id
├─ aria-selected
└─ aria-controls

TabPanel
├─ id
├─ role="tabpanel"
└─ aria-labelledby
```

这样“每日记录 / 最近7天 / 30天复盘 / 数据管理”不再只有视觉切换，而有明确的程序化对应关系。

### 2.2 今日入口后的焦点

从：

- “开始今日记录”；
- “继续上次并记录”；
- “今天决定不练”；

进入记录表单后，键盘焦点转到日期字段。

目的不是自动替用户填写，而是避免视觉已经滚到表单、键盘焦点却仍留在上方按钮的断裂。

### 2.3 安全提示播报

普通保存/导入/复制提示继续使用：

```text
role="status"
aria-live="polite"
```

包含红色安全阻断的提示改为：

```text
role="alert"
aria-live="assertive"
```

红色事件提示框同样使用紧急播报语义。

这只是辅助技术播报优先级，不改变红色事件的业务判定，也不会自动替用户设置红色。

### 2.4 键盘焦点可见

实践工作台内的按钮、链接、输入框、下拉框、文本框与 `summary` 使用统一 `:focus-visible` 轮廓。

### 2.5 触控目标

在 `(pointer: coarse)` 的粗指针/触控环境下：

- 标签页；
- 主/次按钮；
- 链接按钮；
- 折叠区 `summary`；

最小高度为 44px。

异常复选项也增加触控高度，复选框本身不小于 20px。

## 三、真实 Chromium 回归

脚本：

`website/scripts/e2e-practice-accessibility.mjs`

命令：

```text
npm run test:e2e:a11y
```

并已纳入：

```text
npm run test:e2e:daily
```

当前真实浏览器验证：

1. 四个标签都有 `id / aria-controls`；
2. 当前面板有 `role="tabpanel" / aria-labelledby`；
3. 可见表单 `input / select / textarea` 均有可访问名称；
4. 从今日入口进入记录后，焦点进入日期字段；
5. 红色 URL 安全阻断使用 `alert + assertive`；
6. Chromium 390×844 + 触控仿真进入 `pointer: coarse`；
7. 标签页与今日操作区可见触控目标不小于 44px。

通过标识：

```text
[a11y-e2e] 通过：标签页关系、表单名称、动作焦点、红色紧急播报和390px触控目标均有效。
```

## 四、质量门

`npm run practice:check` 已要求：

- 主题入口必须启用 `installPracticeAccessibility`；
- 必须加载 `practice-accessibility.css`；
- 必须存在 `aria-controls / tabpanel / aria-labelledby`；
- 必须存在今日入口后的焦点转移；
- 红色提示必须区分 `alert / assertive`；
- 必须存在 `:focus-visible`；
- 必须存在 `pointer: coarse` 下的 44px 触控基线；
- `test:e2e:daily` 必须包含真实可访问性 Chromium 回归。

---

## 五、仍未自动证明的部分

以下仍必须保留为真机/人工验证，不得写成“已完成”：

- NVDA + Windows Chrome / Edge；
- VoiceOver + macOS Safari；
- VoiceOver + iOS Safari；
- TalkBack + Android Chrome；
- 屏幕阅读器对动态安全提示的实际播报顺序；
- 浏览器缩放 200% / 400% 的完整内容适配；
- 高对比模式；
- 不同系统字体放大；
- 真实手指触控误触；
- Safari 对动态 `details`、焦点和本地文件导入的差异。

因此当前结论只能是：

> Chromium 自动化可访问性基础已建立；真实辅助技术、多浏览器和真机体验仍待验证。
