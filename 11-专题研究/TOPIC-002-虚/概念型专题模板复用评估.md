# TOPIC-002 概念型专题模板复用评估

**日期：** 2026-08-07
**对象：** `templates/概念型专题工作包/` 与《概念型专题生产规范 V0.2》
**样本：** TOPIC-001「静」首轮建立 + TOPIC-002「虚」第二次完整复用
**目的：** 判断当前概念型专题生产线哪些必须保留、哪些需要改名/合并、哪些应按需生成，以及TOPIC-003“心”是否可以继续沿用。

---

## 一、总体结论

**结论：模板体系可以继续复用，但不应原样复制。**

TOPIC-002证明，阶段0—8的主链条是有效的：范围冻结 → 来源核对 → 证据总账 → 概念/争议 → 研究核对 → 安全边界 → 结论摘要/入口 → 反向审查 → 发布验收。这条链条能够阻止材料无限扩张、结论无来源、现代解释倒灌古籍等问题。

同时，TOPIC-002也证明TOPIC-001首轮样板里存在一批“第一次建体系时合理、第二次复用时显得过重”的设计。后续不应继续增加模板，而应做减法。

**推荐：TOPIC-003“心”继续使用该生产线，但先将模板升到V0.3轻量化版本。**

## 二、按产出物分类评估

| 产出/机制 | 分类 | 结论 |
| ---- | ---- | ---- |
| manifest.yml | 必须保留 | 是专题范围、状态、核心问题和阻塞的单一清单，价值高 |
| 专题范围卡 | 必须保留 | 防止研究漂移；但与manifest重复字段可进一步减少 |
| 来源清单 | 必须保留 | 用于材料范围与版本身份管理 |
| 来源核对记录 | 必须保留 | 与来源清单职责不同：一个列清单，一个留核对过程 |
| 证据总账/结论编号表 | 必须保留 | 整个体系最核心文件，必须继续作为结论唯一权威源 |
| 概念卡 | 必须保留 | 作为知识层主要成品，但必须坚持“下游引用证据总账” |
| 争议卡 | 按材料生成 | 有真实解释竞争时建立；不能为模板凑争议 |
| 主张卡 | 按材料生成 | **不应作为阶段3必需产物**；必须先存在可追溯主张来源 |
| 现代研究引用核对表 | 建议改名 | 改为“研究引用核对表”或“文献与现代研究核对表”，以容纳训诂、注疏、人文学术研究 |
| 现代研究卡 | 按需生成 | E1—E5适合实证研究，不适合强套所有人文学术材料 |
| 专题安全边界 | 必须保留但轻量化 | A类专题只写真正相关的误读/传播边界；允许大量“不适用” |
| 专题结论摘要 | 必须保留 | 连接研究层与入口层，能明显降低问题卡重复维护结论的风险 |
| 问题卡 | 按用户需求生成 | 数量不固定；由核心问题和常见误解决定 |
| 辨析卡 | 按概念混淆点生成 | 数量不固定；只处理真正高频、会造成误读的概念对 |
| 反向审查记录 | 必须保留 | 是发现“项目框架历史化、现代研究过用”等问题的重要步骤 |
| 发布验收记录 | 必须保留 | 但需允许“研究侧完成、平台侧延期”的分层状态 |
| 模板复用评估 | 仅样板期需要 | TOPIC-002完成后可转为项目级版本迭代记录，不必每个专题重复做完整评估 |

## 三、七个明确需要修改的模板问题

### 1. 主张卡不能是阶段3默认必需品

TOPIC-002原计划候选建立“虚=空无”“致虚=具体冥想方法”两张主张卡，但实际核对后没有找到足够明确、可追溯的具体主张来源。

如果为了完成模板而建卡，会产生“项目自己先制造一个主张，再自己反驳”的伪研究。

**修改建议：** 阶段3产出写成“概念卡 + 争议卡（如有）+ 主张卡（如有明确来源）”。

### 2. 阶段4不应只叫“现代研究核对”

TOPIC-002真正影响C04—C06的材料包括：王弼、郭象、成玄英等注疏，朱谦之等校释，以及现代人文学术论文。

如果阶段4只允许“现代研究”，会迫使传统概念专题错过最重要的解释史材料。

**修改建议：** 改为“文献解释与现代研究核对”或“研究引用核对”。

### 3. E1—E5不能强套传统注疏/人文学术

E等级原本服务现代实证研究。传统注疏、校勘、思想史论文的可信度判断逻辑不同。

**修改建议：** 研究引用核对表允许“证据等级不适用”，改用“材料类型 + 文本可靠度 + 用途 + 能/不能支持”。

### 4. 问题卡、辨析卡数量不得硬编码

TOPIC-002实际需要6张问题卡即可覆盖C01—C06，高价值辨析点为5组。强行做到10张问题卡只会拆出低价值问题。

**修改建议：**
- 问题卡：建议3—8张，按核心问题与真实用户误解决定；
- 辨析卡：建议2—6张，按概念混淆密度决定；
- 不设最低凑数要求，只要求覆盖正式结论与关键误读。

### 5. 关键补充文献要有正式身份

《管子·心术上》不是阶段0冻结的四部核心文献，却直接包含“虚其欲”等重要材料。

若只能在“核心/辅助”二选一，容易出现“名义辅助、实际核心证据”的隐性错位。

**修改建议：** manifest增加“关键补充文献/关键补充证据”层级：不改变冻结范围，但允许直接支撑结论并强制标注身份。

### 6. 项目分析框架必须允许降级

TOPIC-001留下“虚偏清除、静偏安定”的工作性说法。TOPIC-002再次核对后，不能把它升级为古代统一定义，只能继续降级为比较框架。

**修改建议：** 模板明确加入：后续专题有权把前专题的“暂定框架”降级、修订或撤回；回写时保留修改记录。

### 7. A类安全模板需要更轻

纯概念专题并不必然涉及呼吸、静坐、身体异常。若每次照抄完整风险模板，会制造与专题无关的风险内容。

**修改建议：** A类安全边界采用最小结构：
1. 内容边界；
2. 最相关的误读转实践风险；
3. 明确不提供什么；
4. 对项目级安全边界的引用；
5. 其余项目写“不适用”。

## 四、流程层面的改进

### 4.1 保留阶段0—8，但允许小阶段合并执行

阶段编号有助于状态管理，不建议删除；但实际执行中可以按批次合并：

- 批次一：阶段0—2（范围/来源/证据）；
- 批次二：阶段3—5（解释/研究/安全）；
- 批次三：阶段6—8（入口/反审/发布验收）。

这次TOPIC-002验证了三批次机制比逐阶段等待确认更高效。

### 4.2 结论唯一权威源必须继续坚持

TOPIC-002最大的稳定性来自C01—C06只在证据总账维护。概念卡、争议卡、摘要、问题卡、辨析卡只引用编号。

**此规则不建议削弱。**

### 4.3 入口层必须晚于研究层

问题卡和辨析卡应在证据总账、概念/争议、研究核对、安全边界完成后生成。

TOPIC-002证明这样可以避免入口层“为了好懂”擅自增加新结论。

### 4.4 研究轨和平台轨应分开

本次用户明确要求不处理网站，而研究侧仍可完整推进到反向审查和条件发布验收。

**建议项目正式区分：**
- 研究轨：TOPIC/DAOYIN/MEDOBS，一次只激活一个研究包；
- 平台轨：WEB/TOOL/DATA，可处理展示、构建、搜索、部署；
- 平台轨不得修改研究结论，只消费研究轨的已审核产物。

这样可以解决“研究工作包冻结网站，但现实中网站仍需维护”的治理冲突。

## 五、对TOPIC-003“心”的具体建议

TOPIC-003不应复制TOPIC-002全部文件数量，而应采用以下最小启动包：

1. manifest + 范围卡；
2. 3—4个核心问题；
3. 冻结核心文献范围；
4. 原文索引/来源核对；
5. 证据总账；
6. 概念-0003重构；
7. 按材料建立争议/主张；
8. 研究引用核对；
9. A类安全边界；
10. 结论摘要；
11. 实际需要的问题/辨析入口；
12. 反向审查 + 发布验收。

**特别注意：** “心”比“静/虚”跨度更大，必须在阶段0更严格限制历史时期和语义范围，否则极易扩展成中国思想史总专题。

## 六、是否需要大改架构

**不需要。**

TOPIC-002没有发现必须新增顶层目录、全新证据等级、全新卡片类型或全新数据库结构的问题。当前问题主要属于：

- 模板文字过硬；
- 必需/可选产物边界不清；
- 数量写死；
- 现代实证研究模板与人文研究混用；
- 研究轨/平台轨治理未明确。

这些都可以通过V0.3规范升级解决，不需要重新搭项目架构。

## 七、最终分类清单

### 必须保留

- manifest；
- 范围冻结；
- 来源清单/核对记录；
- 证据总账与结论编号；
- 概念卡；
- 研究引用核对；
- 专题安全边界；
- 结论摘要；
- 反向审查；
- 发布验收。

### 按需生成

- 主张卡；
- 争议卡；
- 现代研究卡；
- 问题卡；
- 辨析卡；
- 假说卡。

### 建议修改而非删除

- 阶段4名称与证据字段；
- A类安全边界模板；
- 阶段8支持“研究侧/平台侧”分层验收；
- 工作包中的固定数量要求。

### 不建议继续增加

- 新的顶层目录；
- 新的通用等级体系；
- 为每个专题新增专用卡片类型；
- 为追求“全链路完整”而制造没有真实来源的卡片。

## 八、评估结论与后续决策

**模板复用结论：通过（建议升版后继续使用）。**

建议在TOPIC-002最终验收后执行一次项目级小改版：

`概念型专题生产规范 V0.2 → V0.3`

只做上述轻量化修订，不新增架构。完成后再激活TOPIC-003“心”。
