# 节点关系规范

## 一、目的

问道志的知识图谱不能只表达“两个节点有关”，还必须说明：

- 是什么关系；
- 关系适用于哪个时代、文本或传统；
- 关系依据是什么；
- 是否存在争议；
- 是否暗含历史方向或因果。

本规范用于避免把知识导航图误写成师承链、发展链或修炼步骤。

## 二、节点类型

当前允许：

- `classic`：经典
- `person`：人物
- `school`：流派或传统分类
- `concept`：概念
- `method`：方法
- `stage`：阶段
- `route`：路线
- `research`：研究与专题

后续若发现“思想传统、宗教宗派、修炼传统”长期混在 `school` 中无法准确表达，再通过附加字段细分，不在本阶段频繁增加顶层类型。

## 三、关系通用结构

```yaml
- target: concept.jing
  relation: related_to
  scope: 《道德经》第十六章虚静并提语境
  evidence: A
  source_refs:
    - source.daodejing.16
```

必填或强烈建议字段：

- `target`：目标节点；
- `relation`：关系类型；
- `scope`：适用范围；
- `evidence`：证据等级；
- `source_refs`：来源引用。

若关系存在明显争议，应增加争议卡或使用 `disputed_relation`。

## 四、第一阶段核心关系类型

### 1. `related_to`

一般关联。

特点：

- 通常视为语义上的对称关系；
- 不表示时间先后；
- 不表示师承；
- 不表示因果；
- 不表示修炼步骤。

例如：

```text
虚 related_to 静
心 related_to 气
身 related_to 心
```

在文件中不强制双方都重复保存同一条边。构建程序应将其识别为对称关系，避免人工维护两份完全相同的数据。

### 2. `source_of`

来源关系，具有方向。

例如：

```text
《道德经》 source_of 某概念解释
```

必须能指出具体文本、章节或可靠研究依据。

### 3. `authored`

人物与作品的较确定著作关系。

使用条件：

- 现有历史研究对作者关系相对稳定；
- 即使文本后来有增补，也能较可靠地确认核心作品与该人物的作者关系。

例如张伯端与《悟真篇》核心文本可使用 `authored`。

不得使用 `authored` 抹平传统托名或复杂文本形成史。

### 4. `traditional_attribution`

传统作者归属、托名或后世归属关系，具有方向。

用于以下情形：

- 传统长期把某作品归于某人物，但现代研究对作者、年代或文本形成存在明显争议；
- 传世文本为复合文本，人物可能与其中部分材料有关，但不能据此认定其撰写全部今本。

例如：

```text
老子 traditional_attribution 《道德经》
庄子 traditional_attribution 今本《庄子》
魏伯阳 traditional_attribution 《周易参同契》
```

该关系必须在 `scope` 中说明争议范围，并优先引用历史研究来源。

### 5. `influences`

思想影响关系，具有方向。

要求比一般关联更高：

- 必须有历史材料或可靠研究支持；
- 不能因为两者概念相似就写成影响；
- 跨数百年的相似术语尤其需要谨慎。

### 6. `develops`

历史发展或理论展开关系，具有方向。

这是高风险关系。

只有在能说明“后者在历史上对前者进行了可证实的发展、重构或体系化”时使用。

不得把：

```text
魏伯阳 → 葛洪 → 张伯端 → 王重阳
```

这种方便理解的知识导航直接写成 `develops` 或师承链，除非逐段有独立历史证据。

### 7. `belongs_to`

归属或分类关系，具有方向。

例如：

```text
某人物 belongs_to 某宗派
某方法 belongs_to 某实践体系
```

需要注意分类的时代性，现代研究分类不自动等于历史人物自我认同。

### 8. `contains`

体系包含关系，具有方向。

例如：

```text
某体系 contains 某阶段
某专题 contains 某子问题
```

不用于表达“受到影响”或“经常一起出现”。

### 9. `practices`

人物、流派或传统与某方法的明确实践关系。

要求有具体材料，不因某宗派“常被认为重视某法”就默认建立。

### 10. `contrasts_with`

对比关系，通常视为对称。

例如用于：

- 不同解释；
- 不同方法；
- 不同宗派的制度差异。

### 11. `disputed_relation`

关系本身存在争议时使用。

必须链接相应争议材料，避免把争议边和正常边混在一起。

## 五、关系方向规则

### 对称关系

第一阶段视为对称：

- `related_to`
- `contrasts_with`

数据层只需保存一条规范边，构建时可以生成双向导航。

### 有向关系

第一阶段视为有向：

- `source_of`
- `authored`
- `traditional_attribution`
- `influences`
- `develops`
- `belongs_to`
- `contains`
- `practices`

反向导航由程序生成，不人工创造一个意义不同但没有定义的反向关系。

## 六、历史链与知识导航必须分开

以下表达只适合知识导航：

```text
《道德经》 → 虚 → 静 → 心斋 → 坐忘
```

它不能自动解释为：

- 《道德经》直接产生心斋；
- 心斋必然经过“静”这一固定步骤；
- 坐忘是心斋的下一阶段；
- 它们属于一条连续师承。

因此正文中的箭头图必须注明其性质：

- 知识导航；
- 历史发展；
- 文本来源；
- 实践步骤；
- 假说。

若未注明，默认只能视为“知识导航”。

## 七、证据等级不是关系强度的万能排序

A级原始文献适合回答“传统文本怎么说”；B级历史研究适合回答“不同文本或流派之间历史上是什么关系”；E级现代研究适合回答“现代可测现象是什么”。

因此不能简单理解为：

```text
A > B > C > D > E
```

在所有问题上都成立。

证据等级首先表示**来源类型和用途**，关系是否成立还要看它回答的具体问题。

## 八、核心概念关系的第一阶段处理

七个核心概念：

- 道
- 气
- 静
- 虚
- 心
- 息
- 身

第一阶段优先使用 `related_to`，只有明确文本或历史证据时才升级为更强关系。

例如：

```text
虚 related_to 静
静 related_to 心
心 related_to 气
心 related_to 身
气 related_to 息
```

这些边的具体含义仍由 `scope` 和 `source_refs` 限定。
