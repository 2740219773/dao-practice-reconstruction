# 知识卡数据模型

## 一、定位

知识卡数据模型用于把 Markdown 内容转换为可被网站、知识图谱和 AI 检索系统直接使用的结构化数据。

字段名保留英文，仅因为后续需要被程序读取；正文与说明继续使用中文。

## 二、通用节点模型

```yaml
id: concept.qi
type: concept
name: 气
summary: 一句话定位
status: draft
period: 先秦至后世发展
systems:
  - 传统生命观
  - 内丹体系
tags:
  - 核心概念
relations: []
sources: []
claims: []
related_topics: []
```

## 三、字段说明

### id

全库唯一标识。建议采用 `类型.拼音或约定短名`，例如：

- `classic.daodejing`
- `person.zhangboduan`
- `school.quanzhen`
- `concept.qi`
- `method.daoyin`

### type

允许值：

- classic：经典
- person：人物
- school：流派或传统分类
- concept：概念
- method：方法
- stage：阶段
- route：路线
- research：研究

`school` 是当前兼容性顶层类型，不代表目录中所有对象都是同一种历史实体。凡 `type: school` 的新版节点应增加 `school_kind`。

### school_kind

仅用于 `school` 节点，第一阶段允许：

- `intellectual_tradition`：思想史传统，例如“先秦道家”“黄老”；
- `religious_order`：具有组织、制度与宗教身份意义的宗教宗派或教团，例如“全真道”；
- `religious_tradition`：历史跨度较长、组织形态多变的宗教传统，例如“正一/天师传统”；
- `practice_tradition`：围绕某类修炼、炼养或技术形成的跨宗派实践传统，例如“丹道传统”；
- `historiographic_category`：主要用于后世或现代研究分类、不能直接等同历史自称的类别。

一个节点如同时具有多重性质，以研究用途最核心的一类为主，并在 `classification_notes` 中说明边界。

### classification_notes

用于记录分类的时代性和研究边界。例如：

```yaml
classification_notes: “先秦道家”是后世思想史分类，不表示战国人物自称属于统一的“道家宗派”。
```

### status

允许值：

- draft：草稿
- review：待审
- published：可发布
- disputed：争议较大
- archived：归档

### systems

记录该节点所属或主要关联的知识体系，例如：

- 老庄思想
- 传统生命观
- 丹道传统
- 全真道
- 导引养生

### relations

关系采用统一对象结构：

```yaml
relations:
  - target: method.neidan
    relation: related_to
    scope: 内丹传统
    evidence: C
    source_refs:
      - source.wuzhenpian.general
```

### sources

沿用《知识图谱来源字段规范》：

```yaml
sources:
  - id: source.daodejing.16
    type: classic
    name: 道德经
    reference: 第十六章
    evidence: A
```

### claims

用于把重要判断从正文中抽离出来，便于后续审校：

```yaml
claims:
  - text: 某一判断
    evidence: B
    source_refs:
      - source.xxx
    status: verified
```

`status` 建议使用：

- verified：已核对
- provisional：暂定
- disputed：存在争议
- todo：待考证

## 四、关系模型

统一关系不追求一次覆盖所有语义，第一阶段控制在以下核心类型：

- authored：较稳定的作者关系；
- traditional_attribution：传统作者归属、托名或复合文本归属；
- founded：人物与可较明确识别的历史宗教组织/运动之创建关系；
- source_of：思想、概念或方法的直接文本来源；
- develops：发展、推进；
- belongs_to：归属；
- influences：影响；
- practices：流派或人物使用某方法；
- contains：体系包含；
- related_to：一般关联；
- contrasts_with：对比关系；
- disputed_relation：关系本身存在争议。

重要关系必须同时记录来源和证据等级。

`founded` 只用于较明确的历史组织或运动创建关系。不能把思想史分类、现代概括类别或后世祖师谱系都写成“创立”。例如王重阳与早期全真运动可使用 `founded`；老子与“先秦道家”则不得使用。

## 五、知识卡与 Markdown 的关系

推荐结构：

```text
Markdown 正文
    ↓
Front Matter 元数据
    ↓
节点数据
    ↓
关系数据
    ↓
网站 / 知识图谱 / AI
```

Markdown 是主要维护入口，结构化数据原则上由元数据和构建脚本生成，避免人工维护两套互相漂移的数据。

## 六、不同卡片的附加字段

### 经典卡

建议增加：

- author_or_attribution
- formation_period
- textual_issues
- major_concepts

### 人物卡

建议增加：

- era
- works
- schools
- historicity

### 流派卡

新版应增加：

- school_kind
- classification_notes
- origin_period
- representatives
- classics
- methods

其中“思想传统、宗教宗派、宗教传统、修炼传统”必须通过 `school_kind` 区分，不再因为位于同一目录就默认属于同一性质。

### 方法卡

建议增加：

- practice_scope
- prerequisites
- risks
- modern_research

### 关系卡

建议增加：

- source
- target
- relation
- scope
- evidence
- source_refs
- disputed

## 七、第一阶段原则

1. 先保证唯一标识和关系稳定，再逐步增加复杂字段。
2. 不把所有 Markdown 段落强行结构化，只抽取检索和图谱真正需要的信息。
3. 来源、证据等级、争议状态属于核心字段，不得作为可选装饰。
4. 结构化数据必须能够回溯到原始 Markdown 和具体来源。
5. `school` 仅是迁移期兼容顶层类型，任何流派/传统节点必须通过 `school_kind` 显式说明其性质。
