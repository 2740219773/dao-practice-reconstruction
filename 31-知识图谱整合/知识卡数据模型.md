# 知识卡数据模型

## 一、定位

知识卡数据模型用于把 Markdown 内容转换为可被网站、知识图谱和 AI 检索系统直接使用的结构化数据。

字段名保留英文，仅因为后续需要被程序读取；正文与说明继续使用中文。

## 二、通用节点模型

```yaml
id: concept.qi
type: concept
name: 气
summary: 一句话定位
status: draft
period: 先秦至后世发展
systems:
  - 传统生命观
  - 内丹体系
tags:
  - 核心概念
relations: []
sources: []
claims: []
related_topics: []
```

## 三、字段说明

### id

全库唯一标识。建议采用 `类型.拼音或约定短名`，例如：

- `classic.daodejing`
- `person.zhangboduan`
- `school.quanzhen`
- `concept.qi`
- `method.daoyin`

### type

允许值：

- classic：经典
- person：人物
- school：流派
- concept：概念
- method：方法
- stage：阶段
- route：路线
- research：研究

### status

允许值：

- draft：草稿
- review：待审
- published：可发布
- disputed：争议较大
- archived：归档

### systems

记录该节点所属或主要关联的知识体系，例如：

- 老庄思想
- 传统生命观
- 丹鼎传统
- 全真道
- 导引养生

### relations

关系采用统一对象结构：

```yaml
relations:
  - target: method.neidan
    relation: related_to
    scope: 内丹传统
    evidence: C
    source_refs:
      - source.xxx
```

关系必须遵循《节点关系规范》。人物与作品尤其需要区分：

- `authored`：作者关系相对确定；
- `traditional_attribution`：传统长期归于某人物，但作者、年代或今本文本形成存在争议。

### sources

沿用《知识图谱来源字段规范》：

```yaml
sources:
  - id: source.daodejing.16
    type: classic
    name: 道德经
    reference: 第十六章
    evidence: A
```

### claims

用于把重要判断从正文中抽离出来，便于后续审校：

```yaml
claims:
  - text: 某一判断
    evidence: B
    source_refs:
      - source.xxx
    status: verified
```

`status` 建议使用：

- verified：已核对
- provisional：暂定
- disputed：存在争议
- todo：待考证

## 四、关系模型

统一关系不追求一次覆盖所有语义，第一阶段控制在以下核心类型：

- authored：较确定作者关系
- traditional_attribution：传统作者归属、托名或复合文本归属
- source_of：思想或概念来源
- develops：发展、推进
- belongs_to：归属
- influences：影响
- practices：流派或人物使用某方法
- contains：体系包含
- related_to：一般关联
- contrasts_with：对比关系
- disputed_relation：关系本身存在争议

重要关系必须同时记录来源和证据等级。

## 五、知识卡与 Markdown 的关系

推荐结构：

```text
Markdown 正文
    ↓
Front Matter 元数据
    ↓
节点数据
    ↓
关系数据
    ↓
网站 / 知识图谱 / AI
```

Markdown 是主要维护入口，结构化数据原则上由元数据和构建脚本生成，避免人工维护两套互相漂移的数据。

## 六、不同卡片的附加字段

### 经典卡

建议增加：

- author_or_attribution
- formation_period
- textual_issues
- major_concepts

### 人物卡

建议增加：

- era
- works
- schools
- historicity

### 流派卡

建议增加：

- origin_period
- representatives
- classics
- methods

### 方法卡

建议增加：

- practice_scope
- prerequisites
- risks
- modern_research

### 关系卡

建议增加：

- source
- target
- relation
- scope
- evidence
- source_refs
- disputed

## 七、第一阶段原则

1. 先保证唯一标识和关系稳定，再逐步增加复杂字段。
2. 不把所有 Markdown 段落强行结构化，只抽取检索和图谱真正需要的信息。
3. 来源、证据等级、争议状态属于核心字段，不得作为可选装饰。
4. 结构化数据必须能够回溯到原始 Markdown 和具体来源。
5. 传统归属与现代历史判断必须分字段或分关系记录，不得互相覆盖。
