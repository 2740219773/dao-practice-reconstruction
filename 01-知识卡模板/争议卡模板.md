# 争议卡模板

本模板依据《基础规范 V0.1》编制，字段键英文值中文

模板版本：V0.2

---

## 一、模板用途

争议卡用于记录一个尚无统一答案、存在至少两种合理解释的问题。

本模板依据《项目总体分期》"争议卡"一节编制：每个争议至少保留两种解释，不得过早合并。

### 使用规则

- 每个争议至少保留两种解释，不得过早合并；
- 不同观点并列保存，不提前选择唯一正确答案；
- 证据不足时保持"暂不判断"；
- 判断发生变化时，同步更新最后修改日期和修改记录。

### 争议问题示例

以下示例来自《项目总体分期》：

- 气是否具有统一含义；
- 丹田是位置、功能还是象征结构；
- 心斋是否属于具体静坐方法；
- 坐忘是否包含主动意念；
- "自然呼吸"与"调息"是否矛盾；
- 筑基是阶段、状态还是一组准备工作。

---

## 二、卡片编号

按《基础规范 V0.1》统一编号体系：

```text
争议-0001
争议-0002
```

流水号按类别独立计数，从 0001 开始，不作废、不复用；被废弃卡片的编号保留，状态标记为"不予采用"或"已归档"。

---

## 三、状态字段

review_status 使用 9 个中文状态：

| 状态 | 含义 |
| ---- | ---- |
| 草稿 | 卡片刚建立，内容可能不完整 |
| 待核对 | 原文、出处、版本或引用尚未完成核对 |
| 来源已核对 | 原始资料已确认，解释仍未审核 |
| 待解释审核 | 原文可靠，翻译、解释或概念关系待审查 |
| 待综合审核 | 内容基本完成，等待整体审核 |
| 已审核 | 符合当前版本规则，可进入正式知识库 |
| 需要修订 | 已发现问题，需要修改 |
| 不予采用 | 存在严重来源、逻辑或安全问题 |
| 已归档 | 被新版本取代，保留用于追溯 |

新建卡片默认状态：草稿。

状态迁移必须同步更新最后修改日期和修改记录。

---

## 四、YAML 字段

```yaml
---
id: 争议-0001
title: 争议问题标题
review_status: 草稿
text_reliability: T2
interpretation_level: I3
counterevidence_status: C1
risk_level: S0
created_at: 2026-08-01
updated_at: 2026-08-01
creator: 创建人员
---
```

### 字段说明

- id：卡片编号，格式为"争议-四位流水号"；
- title：争议问题标题；
- review_status：当前状态，使用 9 个中文状态，默认"草稿"；
- text_reliability：文献可靠度 T1—T5；
- interpretation_level：解释层级 I1—I5；
- counterevidence_status：反证状态 C0—C4；
- risk_level：风险等级 S0—S4；
- created_at：创建日期，格式为 年-月-日；
- updated_at：最后修改日期，格式为 年-月-日；
- creator：创建人员。

等级字母作为正式技术名称保留原样。

争议涉及现代研究时，可增加：

```yaml
modern_evidence: # 现代证据等级 E1—E5 或 EX
mapping_strength: # 对应关系强度 M0—M4
```

## 六、填写要求

- 每个争议至少保留两种解释，没有充分理由不得合并；
- 不同观点必须并列保存，不能只保留一种解释；
- 支持证据和反对证据必须同时整理，不能只收集支持材料；
- 当前判断使用克制语气，不得提前宣布唯一正确答案；
- 争议解决或判断变化时，可建立决策记录卡说明原因，并同步更新本卡修改记录；
- 状态迁移必须同步更新最后修改日期和修改记录。
