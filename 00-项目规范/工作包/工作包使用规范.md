# 工作包使用规范

**文档定位：** 项目推进机制（一个仓库、多个工作包、任何时候只激活一个工作包）。工作包是临时任务视图，不是知识分类；知识卡仍按文献/原文/概念/主张/假说/争议/现代研究/风险资料等类别存放，工作包完成后文件回到原分类，不复制第二套资料。

**背景：** 项目同时推进网站、古籍、概念、现代研究时，注意力会被稀释。研究侧已完成 15 张现代研究卡关键数字复核（8 张全文、7 张摘要），是适合冻结切换的节点。

---

## 一、目录结构

```text
00-项目规范/
└─ 工作包/
   ├─ 工作包使用规范.md        # 本文件
   ├─ WEB-001-网页端视觉升级.md
   ├─ TEXT-001-道德经专题完善.md
   ├─ CONCEPT-001-静概念完善.md
   └─ context/                 # 上下文包（每个工作包一份精简上下文）
      ├─ WEB-001-context.md
      ├─ TEXT-001-context.md
      └─ CONCEPT-001-context.md

CURRENT_FOCUS.md               # 仓库根目录：当前激活的工作包
```

## 二、激活规则与状态机

工作包状态为强制状态机，不允许跳级：

```text
待开始 → 进行中 → 待用户验收 → 已完成 → 已归档
```

- **待开始**：范围卡已建立，未开始执行；
- **进行中**：当前激活的唯一工作包；
- **待用户验收**：工作内容完成，等待项目负责人确认——**强制闸门**：工作包进入此状态后，AI 不得自行激活下一个工作包，必须由项目负责人明确确认（验收通过 → 已完成；发现问题 → 退回进行中修订）后才可切换；
- **已完成**：项目负责人确认验收通过，工作包冻结（可归档）；
- **已归档**：完成登记与验收对照后关闭。

其他规则：

- 任何时候**只激活一个工作包**；其余工作包状态为「待开始」「待用户验收」「已完成」或「已归档」；
- 当前激活工作包记录在根目录 `CURRENT_FOCUS.md`，AI 进入仓库第一眼即可看到边界；无激活工作包时写「当前工作包：无／等待用户验收」；
- 工作包内发现的问题若超出本包范围，只登记到该工作包的「旁支问题」节，不在本轮处理；
- 工作包切换速度受闸门约束：上一个工作包未获项目负责人验收确认，不得开始下一个。

## 三、范围卡模板

每个工作包使用一张范围卡（文件位于 `00-项目规范/工作包/`）：

```markdown
# 工作包编号与名称

## 1. 唯一目标
本工作包最终只解决一个什么问题。

## 2. 允许读取
可以读取哪些目录和文件。

## 3. 允许修改
明确到目录，最好明确到文件。

## 4. 禁止修改
本轮不能碰什么。

## 5. 已知输入
已经具备哪些资料，不重复检索什么。

## 6. 预期输出
最多列 3～5 项。

## 7. 验收标准
满足哪些条件才算完成。

## 8. 旁支问题
发现但不在本轮处理的问题，只登记，不展开。

## 9. 当前进度
待开始／进行中／待用户验收／已完成／已归档。
```

关键约束：「禁止修改」与「旁支问题」两项必须填写——没有这两项，AI 容易从小问题扩展到整个项目。

## 四、每次下任务的固定格式

每轮任务只回答四句话：

```text
本轮唯一目标是什么？
允许修改哪些文件？
明确不处理什么？
满足什么条件就停止？
```

示例（网页设计轮）：

```text
本轮只执行 WEB-001。

唯一目标：
优化问道志首页，不处理知识内容。

允许修改：
website/docs/index.md
website/docs/.vitepress/theme/
website/docs/.vitepress/config.*

允许读取但不得修改：
概念-0001、原文-0001、文献-0001。

禁止：
新建知识卡；
修改原文解释；
补现代研究；
修改证据等级；
扩展其他页面。

本轮输出：
1. 首页设计方案；
2. 首页实际代码；
3. 桌面与手机端检查；
4. 变更清单。

发现旁支问题只记录，不处理。
```

## 五、提交按工作包隔离

提交信息必须带工作包编号，一次提交只属于一个工作包：

```text
feat(WEB-001): 重构首页专题入口与视觉层级
style(WEB-001): 完善原文样板页与移动端
docs(TEXT-001): 完成道德经版本与页码核对
docs(CONCEPT-001): 修订静概念的证据分层
review(CONCEPT-001): 完成静概念公开前审查
```

禁止一次提交混入多个工作包的内容（如改首页 + 补论文 + 修道德经 + 改静概念 + 调整风险模板）——即使改动都正确，也无法审核和回退。

工作包机制本身（本规范、范围卡、CURRENT_FOCUS.md）不属于任何内容工作包，使用 `docs(项目)` 前缀提交。

## 六、上下文包

`context/` 下每个工作包一份精简上下文文件，只保留完成任务真正需要的内容（工作包定位、允许/禁止范围、已知输入、关键现状），**不包含无关知识卡全文**。AI 执行工作包时优先读上下文包，避免每次重新读取整个仓库。

## 七、与知识分类的关系

- 知识分类不变：文献卡／原文卡／概念卡／主张卡／假说卡／争议卡／现代研究卡／风险资料卡；
- 工作包是临时任务视图，如 CONCEPT-001「静」可能引用 3 张原文卡、1 张概念卡、1 张主张卡、1 张争议卡、6 张现代研究卡；
- 工作包完成后，这些文件仍留在原知识分类中。

## 八、工作包清单与顺序

| 编号 | 名称 | 状态 | 建议顺序 |
| ---- | ---- | ---- | ---- |
| WEB-001 | 网页端视觉升级 V1.1 | 待激活（推荐当前激活） | 1 |
| TEXT-001 | 道德经专题完善 | 待激活 | 2 |
| CONCEPT-001 | 静概念完善 | 待激活 | 3 |

顺序理由：先确定展示语言（WEB-001），再把《道德经》来源层做扎实（TEXT-001），最后集中完善「静」的跨文献概念整合（CONCEPT-001）。研究侧刚完成一轮完整复核，此时切换到网页端不会打断尚未收口的研究动作。
