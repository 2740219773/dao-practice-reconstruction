# 概念型专题生产规范 V0.3（轻量化版）

**来源：** TOPIC-001「静」首次完整样板 + TOPIC-002「虚」第二次复用验证
**发布日期：** 2026-08-07
**用途：** TOPIC-003「心」及后续概念型专题的正式生产规范。
**状态：** 当前有效版本；V0.2 保留于仓库作为历史版本，不再作为新专题默认执行规范。
**配套：** `templates/概念型专题工作包/`（实际模板源）、《工作包使用规范》、项目《安全边界 V0.2》。

---

## 一、V0.3 的核心变化

V0.3 不改变阶段 0—8 主链条，而是明确“什么必须做、什么按材料做、什么可以延期”。

1. **主张卡、争议卡、现代研究卡、问题卡、辨析卡、假说卡均按材料生成，不为模板凑数。**
2. 阶段 4 从“现代研究核对”改为**“文献解释与现代研究核对”**：训诂、校勘、历代注疏、人文学术研究、现代实证研究按各自性质使用。
3. E1—E5 只用于适合该等级体系的现代实证研究，不强套传统注疏、训诂或一般人文学术论文。
4. manifest 正式增加**关键补充文献/关键补充证据**身份：可直接支撑结论，但不改变阶段 0 已冻结的核心范围。
5. A 类纯知识专题采用**轻量安全边界**，只处理与本专题真正相关的误读转实践风险；其余项目允许写“不适用”。
6. 问题卡、辨析卡不设固定数量。建议问题卡 3—8 张、辨析卡 2—6 张，仅作经验范围，不是验收门槛。
7. 发布验收允许拆成**研究侧**与**平台侧**：研究侧完成后，网站、搜索、构建、展示等平台工作可以延期，不阻塞研究专题冻结；但平台不得修改研究结论。
8. 后续专题有权对前专题的“项目分析框架”进行降级、修订或撤回，必须保留回写与修改记录。

## 二、阶段 0—8 全链路

| 阶段 | 名称 | 必需产出 | 按需产出 | 停止条件 |
| ---- | ---- | ---- | ---- | ---- |
| 0 | 范围冻结 | manifest + 专题范围卡 | — | 核心问题≤4；核心文献/时间范围冻结；排除范围明确；项目负责人确认激活 |
| 1 | 来源核对 | 来源清单 + 来源核对记录 | 新原文卡 | 关键原文来源可追溯；网络/底本状态明确；异文和阻塞留痕 |
| 2 | 证据总账 | 证据总账 + 结论编号表 | — | 每个核心问题有支持/反对/限定；无依据大结论；结论编号为唯一权威源 |
| 3 | 概念与解释竞争 | 核心概念卡修订 | 主张卡、争议卡、假说卡 | 原文/注家/项目判断分层；按来源生成卡片；不制造伪主张 |
| 4 | 文献解释与现代研究核对 | 研究引用核对表 | 现代研究卡 | 训诂/注疏/人文/实证材料分别标注“能支持/不能支持/用途”；不倒灌古义 |
| 5 | 风险边界 | 专题安全边界 | 相关风险资料引用 | A—D 分类明确；只写真实相关风险；不提供越界操作教程 |
| 6 | 结论摘要与入口 | 专题结论摘要 | 问题卡、辨析卡 | 入口层只引用正式结论；数量按真实用户问题与混淆点决定 |
| 7 | 反向审查 | 反向审查记录 | 自动检查结果 | 来源、结论、风险、状态、一致性逐项检查；问题均有处理或阻塞登记 |
| 8 | 验收与冻结 | 发布/验收记录 | 平台上线记录 | 项目负责人最终验收；研究侧可独立冻结；平台侧可延期 |

### 三批次推荐执行

- **批次一：阶段 0—2**——范围、来源、证据。
- **批次二：阶段 3—5**——概念解释、研究核对、安全边界。
- **批次三：阶段 6—8**——入口层、反向审查、最终验收。

批次机制是推荐执行方式，不强制逐阶段等待；每个批次结束必须有明确状态和停止条件。

## 三、必须保留与按需生成

### 必须保留

- manifest；
- 专题范围卡；
- 来源清单；
- 来源核对记录；
- 证据总账/结论编号；
- 核心概念卡；
- 研究引用核对表；
- 专题安全边界；
- 专题结论摘要；
- 反向审查记录；
- 发布/验收记录。

### 按材料或用户需求生成

- 主张卡；
- 争议卡；
- 假说卡；
- 现代研究卡；
- 问题卡；
- 辨析卡。

**原则：没有可追溯来源，不建主张卡；没有真实解释竞争，不建争议卡；没有真实用户问题，不为数量拆问题卡。**

## 四、证据与结论治理

### 4.1 结论唯一权威源

专题结论只在证据总账维护，编号统一为 `TOPIC-0XX-Cxx`。概念卡、争议卡、摘要、问题卡、辨析卡、安全边界和平台页面只引用编号，不另建第二套完整结论。

### 4.2 关键补充证据

阶段 0 冻结核心范围后，如果后续发现重要材料：

- 不静默扩张核心范围；
- 可登记为“关键补充文献/关键补充证据”；
- 可以直接支撑结论，但必须显式标注补充身份；
- 不得依靠单一补充材料推出超出专题范围的宏观历史结论。

### 4.3 项目分析框架可修订

“项目分析框架”是整理工具，不是历史事实。后续专题若发现前专题框架过强，可以：

- 保留；
- 降级；
- 修订；
- 撤回。

回写时必须保留修改原因、版本与影响范围。

## 五、阶段 4：文献解释与现代研究核对

研究材料至少区分四类：

1. **传统注疏/训诂/校勘**：解释特定文本、字义、异文或解释传统；
2. **现代人文学术研究**：提供解释史、思想史或学术竞争观点；
3. **现代实证研究**：用于现代机制、风险或有限对应；
4. **传播性材料**：仅用于追踪现代误读、流行说法或主张来源。

研究引用核对表必须记录：

- 材料类型；
- 来源/文本可靠状态；
- 能支持什么；
- 不能支持什么；
- 专题实际用途；
- 是否存在过度使用。

**E1—E5 仅在适用时填写；不适用时明确写“不适用”，不得为统一字段强行评级。**

---

## 六、阶段 5：安全边界分流

### A 类纯知识专题

采用最小结构：

1. 内容边界；
2. 最相关的“误读 → 实践化”风险；
3. 明确不提供的操作；
4. 与项目级安全边界的关系；
5. 其他风险项目如不相关，明确写“不适用”。

不得为了模板完整性制造呼吸、盘坐、异常体验等无关风险内容。

### B/C/D 类专题

按项目《安全边界 V0.2》展开专项风险、停止条件、异常事件与公开限制。C/D 类不得因专题研究完成自动获得公开实践许可。

---

## 七、阶段 6：问题卡与辨析卡

问题卡、辨析卡属于**入口层**，不是新的研究层。

### 问题卡

- 建议经验范围：3—8 张；
- 来源：核心问题、常见误读、真实用户问题；
- 必须覆盖主要正式结论与关键边界；
- 不新增证据和结论。

### 辨析卡

- 建议经验范围：2—6 张；
- 只处理高频、会造成理解错误的概念对；
- 项目比较性判断必须标明，不伪装成原文定义。

数量不是验收指标，**覆盖质量优先于数量**。

---

## 八、研究轨与平台轨

项目正式区分两条轨道：

### 研究轨

- TOPIC / DAOYIN / MEDOBS；
- 同一时段只激活一个研究工作包；
- 负责“研究结论是什么”。

### 平台轨

- WEB / TOOL / DATA；
- 可处理页面、构建、搜索、数据生成、部署等工程工作；
- 只能消费研究轨已经审核的产物；
- **不得修改研究结论本身。**

阶段 8 允许记录：

- 研究侧：通过/有条件通过/未通过；
- 平台侧：已完成/延期/不适用。

研究侧最终验收通过后，可以冻结专题，即使平台侧延期。

---

## 九、外部阻塞与冻结

指定底本、纸本页码、版权获取等外部阻塞：

- 必须登记；
- 不静默跳过；
- 可按影响范围判断是否阻塞后续研究；
- 若不影响主体结论，可在“可公开草稿”状态下冻结研究侧；
- 正式公开升级条件由发布验收记录单独维护。

专题冻结条件：

1. 阶段 0—8 研究侧完成；
2. 结论编号一致；
3. 反向审查完成；
4. 项目负责人最终验收；
5. 未解决事项均已登记为阻塞/旁支，而非隐藏。
