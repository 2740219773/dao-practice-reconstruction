**来源：** TOPIC-001 静专题全链路样板（2026-08-03 至 2026-08-04 跑通）
**用途：** 供 TOPIC-002（虚）及后续概念模块直接复用——从范围冻结到发布验收的**全链路外壳流程**。本规范只描述"流程外壳"，各专题的具体结论由各专题产出。
**状态：** 已由 TOPIC-001 完整验证；TOPIC-002 启用时按本规范执行并反馈修订。
**配套：** 00-项目规范/工作包/工作包使用规范.md（状态机）；概念型内容模板 V0.1（各产出物模板）。

## 一、十环节全链路（每环节有产出物与验收点）

| 环节 | 产出物 | 验收点 |
| ---- | ---- | ---- |
| 0. 范围冻结 | manifest.yml（单一专题清单） | 核心问题固定、核心原文/固定现代研究清单就位 |
| 1. 来源核对 | 来源核对记录 + 原文卡双字段（网络文本/指定底本核对状态） | 核心原文核对状态逐张明确，异文与页码留痕 |
| 2. 证据总账 | 证据总账.md（Q 问题结论 + 证据清单 + 结论编号表） | Q 问题所有判断有完整证据清单 |
| 3. 概念与主张争议 | 概念卡/主张卡/争议卡修订（引用结论编号） | Q 问题结论有依据标注，来源等级三字段齐全 |
| 4. 现代研究核对 | 研究引用核对表（每张研究卡能支持/不能支持/用途/过度使用检查） | 固定研究卡逐一标注，未被过度使用 |
| 5. 风险边界 | 专题安全边界页（专项风险 + 异常分级 + 公开限制） | 压念/静坐/不良体验等专项风险覆盖 |
| 6. 网站公开 | 公开版页面（仅专题引用卡建页，最小扩展） | 状态标签与核对状态可见，无死链 |
| 7. 反向审查 | 反审记录（11 项检查逐项留痕） | 11 项全部过一遍，含"是否把现代研究强行对应古籍" |
| 8. 发布验收 | 发布审核报告 + 用户验收记录 | 公开内容齐备、不该公开的已排除、风险标签完整 |
| 9. 模板提取 | 通用生产规范 + 概念型内容模板 | 流程与模板可复制到下一个专题 |

**停止条件：** 全部环节完成并通过项目负责人验收；任何一项卡住（如底本实物阻塞）时如实登记阻塞并暂停对应环节，不静默跳过。

## 二、核心原则（TOPIC-001 验证有效）

1. **一次只激活一个工作包**（串行机制）；TOPIC-001 验收前不扩展其他模块；
2. **结论唯一权威源**：专题结论只在证据总账维护（结论编号表 TOPIC-001-Cxx）；概念/主张/争议/安全页/公开页只引用编号，不重复维护完整结论；
3. **现代研究只作限定/反限**：不把现代研究当作传统文本结论的证明或否定（"能支持什么/不能支持什么"双栏结构）；
4. **风险优先**：不提供操作教程；异常体验首先作为安全事件记录；公开页带风险标签；
5. **用户入口链**：正式研究 → 专题结论（编号）→ 问题卡/辨析卡（引用编号）→ 安全说明——入口层卡引用现有正式知识，不重新研究；
6. **状态闭环**：AI 整理内容须经项目负责人复核（去掉"AI 整理待复核"）；公开页生成物不入 Git（.gitignore 忽略详情页，保留 index.md）。

---

## 三、外部阻塞处理

- 指定底本实物复核（纸质点校本）为常见阻塞项：登记于 manifest 与来源核对记录，不阻塞其他环节；公开页维持「可公开草稿」直至复核完成；
- 阻塞项不静默跳过——在发布审核报告的"外部阻塞登记"节如实列出。
