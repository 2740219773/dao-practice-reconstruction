## 一、阶段 0—8 全链路（每阶段有产出物与停止条件）

| 阶段 | 名称 | 产出物 | 停止条件 |
| ---- | ---- | ---- | ---- |
| 0 | 范围冻结 | manifest.yml + 专题范围卡 | 核心问题不超过 4 个；核心文献范围已冻结；明确排除范围已明确；不再随意扩展专题；项目负责人确认激活 |
| 1 | 来源核对 | 来源清单 + 来源核对记录 | 每条关键原文有来源；网络文本/指定底本双核对状态明确；异文和底本阻塞已登记 |
| 2 | 证据总账 | 证据总账（结论编号表） | 每个核心问题有支持、反对、限定材料；结论有编号；不存在无依据结论；结论编号表为唯一权威源 |
| 3 | 概念与主张争议 | 概念卡/主张卡/争议卡修订 | 概念、主张、争议分开；项目判断和原文判断分开；不把整理框架写成古代原说；引用结论编号不重复维护结论 |
| 4 | 现代研究核对 | 研究引用核对表 | 现代研究用途明确；不用于直接证明传统机制；局限和反限材料完整；未被过度使用 |
| 5 | 风险边界 | 专题安全边界 | 明确专题属于 A—D 哪一类；明确可以公开什么；明确不提供什么；专项风险与 L1—L3 异常分级覆盖 |
| 6 | 结论摘要 | 专题结论摘要 | 八节结构齐备；全部引用结论编号；用户入口不新增研究结论 |
| 7 | 反向审查 | 反向审查记录 | 来源、结论、风险、公开状态、一致性全部检查（11 项）；所有问题有记录 |
| 8 | 发布验收 | 发布验收记录 | 构建/公开检查通过；验收记录完成；专题状态冻结 |

**停止条件：** 全部阶段完成并通过项目负责人验收；任何一项卡住（如底本实物阻塞）时如实登记阻塞并暂停对应环节，不静默跳过。

**阶段 0 未完成时不得大量采集材料。**

## 二、核心原则（TOPIC-001 验证有效）

1. **一次只激活一个工作包**（串行机制）；TOPIC-001 验收前不扩展其他模块；
2. **结论唯一权威源**：专题结论只在证据总账维护（结论编号表 TOPIC-0XX-Cxx）；概念/主张/争议/安全页/公开页只引用编号，不重复维护完整结论；
3. **现代研究只作限定/反限**：不把现代研究当作传统文本结论的证明或否定（"能支持什么/不能支持什么"双栏结构）；两类证据不合并为同一种证明；
4. **风险优先**：不提供操作教程；异常体验首先作为安全事件记录；公开页带风险标签；
5. **用户入口链**：正式研究 → 专题结论（编号）→ 问题卡/辨析卡（引用编号）→ 安全说明——入口层卡引用现有正式知识，不重新研究；
6. **状态闭环**：AI 整理内容须经项目负责人复核（不长期保留"AI 整理待复核"状态）；修改记录六列（版本/日期/修改内容/修改原因/修改人员/审核状态）；公开页生成物不入 Git。

## 三、外部阻塞处理

- 指定底本实物复核（纸质点校本）为常见阻塞项：登记于 manifest 与来源核对记录，不阻塞其他环节；公开页维持「可公开草稿」直至复核完成；
- 阻塞项不静默跳过——在发布验收记录的"外部阻塞登记"节如实列出。
