### 1.1 采集观察层细分（框架收口）

| 子类 | 目录 | 程序处理 |
| ---- | ---- | ---- |
| 结构化观察记录 | 20-社区观察 | **OBSERVATION_DIRS**（由读取器扫描，记录结构化字段，不进入公开流程） |

> 说明：12/13/15 归入采集观察层的"非卡片资料池"，只在目录层面归层，不纳入 `OBSERVATION_DIRS` 扫描——避免把参考资料索引或参考网站库强行改造成知识卡记录。

### 分层规则

1. **数据不迁移**：目录暂不搬迁，本图只定义逻辑分层；程序按分组读取，网站按分组统计；
2. **统计口径**：网站「知识卡总计」**只计正式知识层**；「公开页面总数」= 正式知识已公开 + 用户入口已公开（分别统计，口径一致）；用户入口节点、社区观察记录、内部治理记录单独统计，不混入知识卡总数；
3. **公开边界**：只有正式知识层与用户入口层的「可公开草稿／正式公开」内容进入网站；社区观察与治理记录默认不公开（社区观察中的问题可转化为问题卡后公开）；
4. **来源可信等级**：正式知识层与用户入口层填写「来源可信等级」；采集观察层与治理记录层不填写（见《来源可信等级规范》）。

## 二、四类相邻类型的边界与转化

### 2.1 辨析卡 与 争议卡

| 维度 | 辨析卡 | 争议卡 |
| ---- | ---- | ---- |
| 对象 | 两个术语的边界 | 一个仍有多方立场的问题 |
| 目标 | 说明哪里相同、哪里不同、能否互换 | 保存不同观点、依据和未决问题 |
| 结论 | 通常可形成相对稳定的结论 | 不强求统一结论 |

**转化规则：**

```text
尚无稳定结论 → 争议卡
边界已经足够清晰 → 辨析卡
辨析过程中发现不可调和的分歧 → 拆出争议卡
```

### 2.2 社区观察 与 当代传播资料卡

| 维度 | 社区观察卡 | 当代传播资料卡 |
| ---- | ---- | ---- |
| 对象 | 普通评论、高频问题、体验样本 | 具体视频、课程、作者、账号、书籍或传播体系 |
| 记录 | "用户在说什么" | "某个传播者具体说了什么、依据是什么" |
| 用途 | 发现需求、收集问题 | 正式分析传播材料 |

**转化规则：**

```text
普通评论、高频问题、体验样本 → 社区观察卡（20-社区观察/）
值得正式分析的传播者/课程/账号 → 当代传播资料卡（14-当代传播资料卡/）
```

### 2.3 问题卡 与 专题页

- 问题卡只保留：问题、简短回答、关联节点、阅读路线；
- 完整论证放在概念卡、争议卡和专题页中；
- **同一答案不维护两份**：问题卡的回答指向正式知识卡，不重复论证。

### 2.4 AI 审校 与 反向审查

| 维度 | AI 审校记录 | 反向审查报告 |
| ---- | ---- | ---- |
| 对象 | 单张卡或单个页面 | 整个专题 |
| 检查 | 机械性检查（引用/术语/时期/安全） | 结论、反证、风险与发布条件综合审核 |
| 位置 | 21-人工智能审校/（治理记录） | reports/ |

**规则：AI 审校不能替代专题反向审查。**

## 三、哪些记录不是"知识卡"

按本图分层，以下类型**不是知识卡**，不进入知识卡统计、不按知识卡公开字段校验：

| 类型 | 本质 | 为什么不是知识卡 |
| ---- | ---- | ---- |
| AI 审校记录 | 治理记录 | 检查留痕，不是内容本身；无来源可信等级、无网站发布状态 |
| 社区观察卡 | 输入数据与需求样本 | 不得作为权威答案；不进入知识总数与公开生成循环 |
| 项目决策 | 治理记录 | 决策留痕，与原文/概念/研究不同类 |
| 问题卡 | 导航入口 | 问题本身无"可信不可信"；有可信度的是答案与关联证据 |

程序分组与统计口径据此执行（见《项目结构总图》第一节与读取知识卡.mjs）。
