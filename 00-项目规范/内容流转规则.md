# 内容流转规则（P1）

**日期：** 2026-08-03
**定位：** 全项目内容流转规则——明确"原始资料/社区观察如何进入正式知识，结论如何在专题内流转"。内容侧规则，不涉及网站。
**背景：** 内容体系评审（2026-08-03）：研究层强、用户入口层弱、结论源分散。本规则确立两条流转路径与单一结论源原则，防止个人体验/社区结论冒充正式知识、防止结论在多文件重复维护。

---

## 一、正式知识流转路径

```text
原始资料
  → 文献卡／原文卡／现代研究卡（来源核对、证据分级）
  → 概念／主张／争议（证据分层、多观点并列）
  → 专题证据总账（Q 问题结论 + 结论编号，唯一权威源）
  → 专题结论摘要（中间层：七节摘要，引用结论编号）
  → 问题卡／辨析卡（用户入口：引用结论编号，不重新研究）
```

### 各环节职责

| 环节 | 职责 | 禁止 |
| ---- | ---- | ---- |
| 原始资料 | 采集（12-待处理）／索引（13-参考资料）／网站参考（15-参考网站） | 直接进入概念/主张 |
| 文献/原文/现代研究卡 | 来源核对、版本留痕、证据分级（T/E/M/R/C/S） | 未核对即引用 |
| 概念/主张/争议卡 | 证据分层、多观点并列、结论有依据 | 结论无编号即写死 |
| **专题证据总账** | **Q 问题结论唯一权威源**：结论编号表（TOPIC-001-Cxx）+ 证据清单 | **其他文件不得重复维护完整结论** |
| 专题结论摘要 | 中间层：是什么/不是什么/可确认/不可确认/争议/安全边界/延伸 | 不重新研究、不新增证据 |
| 问题卡/辨析卡 | 用户入口：引用结论编号与正式知识 | 不重新研究、不充当权威答案 |

---

## 二、社区与个人资料流转路径

```text
社区评论／个人体验
  → 社区观察（20-社区观察：只记录问题与需求）
  → 提炼真实问题
  → 问题卡（问题-xxxx：答案从正式知识来）
  → 回到正式知识寻找答案（证据总账/概念/原文）
```

### 硬规则

- **社区观察只转化"问题与需求"，不转化社区结论为权威答案**（《项目结构总图》采集观察层）；
- **个人体验不能直接转成概念结论或传统机制证明**（安全边界 V0.2 §2.3：主观真实不等于解释正确）；
- 个人体验若涉及异常，先走安全事件记录（L1—L3），不解释为突破/排病/境界；
- 个人体验进入正式知识须先转成"观察记录"→"问题"→ 由正式知识回答，不得直接写入概念/主张结论。

---

## 三、结论唯一权威源规则（2026-08-03 确立）

1. **专题结论只在证据总账中维护**（结论编号表 TOPIC-001-Cxx）；
2. 概念卡、主张卡、争议卡、安全边界页、公开页、问题卡、辨析卡**只引用结论编号与状态**，不重新维护一份完整结论；
3. 修改结论 → 只改证据总账结论编号表与对应证据清单；引用方同步更新引用（引用变更需在修改记录中注明）；
4. 状态枚举：暂定／当前不支持／支持／限定／不采用（见证据总账）。

## 四、工作包串行原则

- 任何时候只激活一个工作包（工作包使用规范）；
- **TOPIC-001 验收前不扩展**"虚、心、气、息、身"（TOPIC-002~006）、八段锦（DAOYIN-001）、医学观察（MEDOBS-001）——保持串行，防并行破坏既有产出；
- DAOYIN-001 启动前先区分版本谱系（历史资料/不同门派/国家体育总局标准化/临床干预方案/网络改编），坚持导引术目录规则既定原则，不先收集动作教程。
