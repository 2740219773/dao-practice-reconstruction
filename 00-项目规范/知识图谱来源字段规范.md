# 知识图谱来源字段规范

## 一、目的

为知识图谱中的节点和关系建立统一、可追踪的来源机制，避免：

- 只有结论，没有依据；
- 同一原文被不同节点重复创建成多个来源；
- 经典原文、传统解释、历史研究和现代研究混在同一层；
- 后续网站或图谱无法判断两个 `source.*` 是否实际上指向同一材料。

字段名保留英文仅用于程序解析，说明和正文保持中文。

## 二、来源对象结构

推荐统一使用：

```yaml
sources:
  - id: source.daodejing.16
    type: classic
    name: 道德经
    reference: 第十六章
    evidence: A
    verification: partial
```

核心字段：

- `id`：全库唯一来源标识；
- `type`：来源类型；
- `name`：文献或研究名称；
- `reference`：章节、篇名、页码或具体位置；
- `evidence`：证据来源层级；
- `verification`：核对状态。

可选字段：

- `edition`：底本或版本；
- `author`：作者或传统归属；
- `year`：年代；
- `url`：网络核对地址；
- `notes`：版本争议、托名等说明。

## 三、来源类型

### `classic`

古代经典、原始文献、历史原文。

例如：

- 《道德经》；
- 《庄子》；
- 《管子·内业》；
- 《悟真篇》。

主要用于回答“传统文本怎么说”。

### `historical`

现代历史学、思想史、宗教史、文献学研究。

主要用于回答：

- 成书年代；
- 作者问题；
- 流派形成；
- 文本影响；
- 历史演变。

### `traditional`

后世传统注解、宗派内部解释、师承解释。

记录的是“传统内部如何理解”，不自动等于历史事实或现代科学结论。

### `modern`

现代哲学、文化研究、医学、心理、生理等研究。

主要用于现代比较和可测现象研究，不能直接替代古代文本来源。

### `project`

问道志内部已经完成的专题证据总账、来源核对记录等。

例如：

- TOPIC-001 静专题证据总账；
- TOPIC-002 虚专题证据总账。

`project` 不是新的外部证据，它是对上游来源的整理入口。引用它时仍应能继续追溯到原始来源。

## 四、来源 ID 命名规则

第一阶段统一采用：

```text
source.<文献短名>.<定位>
```

例如：

```text
source.daodejing.16
source.daodejing.55
source.zhuangzi.renjianshi.xinzhai
source.zhuangzi.dazongshi.zuowang
source.neiye.xinjingqili
source.zuowanglun.shouxin
```

项目内部研究来源统一：

```text
source.project.topic001.jing
source.project.topic002.xu
```

旧版概念卡等内部材料统一：

```text
source.project.legacy.concept0001
source.project.legacy.concept0002
```

## 五、命名原则

### 1. 同一来源只能有一个主 ID

例如《庄子·人间世》心斋段落不应同时长期存在：

```text
source.zhuangzi.xinzhai
source.zhuangzi.renjianshi
source.zhuangzi.renjianshi.xinzhai
```

第一阶段规范主 ID 为：

```text
source.zhuangzi.renjianshi.xinzhai
```

其他旧 ID 进入别名表，在迁移完成后停止新增。

### 2. 篇章优先于现代主题命名

来源 ID 应尽量反映原始文本位置，而不是项目对它的解释。

推荐：

```text
source.neiye.xinjingqili
```

不推荐：

```text
source.neiye.jing
```

后者容易把“静”这一项目主题误写成原文唯一定位。

### 3. 全书级来源只能作为临时占位

例如：

```text
source.cantongqi.general
```

只允许在尚未完成章句细分时临时使用，并应标记 `verification: todo`。正式发布的重要判断应尽量落到具体章节、句段或版本位置。

### 4. 版本问题必须单独记录

同一句在不同底本中存在文字差异时，不要为了统一 ID 隐藏版本差异。

可以使用同一逻辑来源 ID，同时增加：

```yaml
edition: 王弼本
notes: 郭店简本相关文字待复核
```

若差异大到影响结论，应拆分为独立来源记录。

## 六、核对状态

建议统一：

- `verified`：指定来源或底本已经核对；
- `partial`：网络文本或部分版本已核对，最终底本复核未完成；
- `todo`：仅建立定位，尚未核对；
- `disputed`：来源本身存在重要争议。

注意：来源 `verified` 不代表基于它作出的所有解释都自动 `verified`。

## 七、关系来源

关系必须使用 `source_refs` 回指统一来源 ID：

```yaml
- source: concept.xu
  target: concept.jing
  relation: related_to
  scope: 《道德经》第十六章虚静并提语境
  evidence: A
  source_refs:
    - source.daodejing.16
```

不得只写：

```yaml
source:
  - 道德经
```

因为这种写法无法定位具体依据。

## 八、项目证据与原始来源的关系

推荐追溯链：

```text
知识判断 / 关系
    ↓
source.project.topicXXX
    ↓
原文卡 / 来源核对记录
    ↓
source.<经典>.<篇章或句段>
    ↓
具体底本或研究版本
```

项目专题只是证据组织层，不应成为无法继续追溯的终点。

## 九、当前核心概念迁移期处理

七个核心概念已经存在部分命名漂移，例如：

- `source.zhuangzi.xinzhai`
- `source.zhuangzi.renjianshi`
- `source.zhuangzi.renjianshi.xinzhai`

以及：

- `source.neiye.jing`
- `source.neiye.xinjing`
- `source.neiye.xingshen`

迁移期原则：

1. 不立即大规模替换所有历史文件；
2. 先建立来源注册表和别名；
3. 新增数据一律使用规范主 ID；
4. 后续批量迁移旧节点；
5. 完成迁移后禁止旧别名继续作为主来源 ID。

## 十、基本原则

- 来源和观点分离；
- 来源类型与证据用途分离；
- 传统解释不等于现代事实；
- 不明确来源的内容标记待考证；
- 人工智能生成内容必须经过来源检查；
- 同一来源只维护一个规范主 ID；
- 任何重要关系最终必须能追溯到具体原文或可靠研究。
