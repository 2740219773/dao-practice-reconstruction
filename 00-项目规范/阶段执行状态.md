## 六、V2.3 30天与阶段复盘

新增“30天与阶段”标签页。

30天分布区分：

```text
实际练习
主动决定不练
无记录
黄色事件
红色事件
```

“无记录”只表示当前浏览器没有该日日志，不推断当天一定没有练习。

### 四类基础能力

只判断“记录支持状态”：

- 身体适应；
- 呼吸自然度；
- 注意发现与返回；
- 日用迁移。

允许状态：

```text
记录支持稳定
记录支持部分稳定
尚未稳定
记录不足
因安全原因暂停
```

这些状态不是客观能力认证、医学评估或修炼境界。

### 阶段方向

允许：

- 继续当前基础阶段并观察；
- 继续当前阶段，先补足记录；
- 优先回退、缩短或暂停相关单元；
- 回到已审查负荷后再评估；
- 因安全原因暂停并处理异常；
- 可以讨论下一阶段或分流。

其中最后一项必须同时显示：

> **这不是自动晋级。**

系统不会自动解锁静修深化、导引深化或任何中高风险内容。

丹道继续默认：

```text
research_only
```

## 七、阶段判断优先级

固定为：

```text
红色事件
↓
现实功能影响 / 重复黄色 / 多项尚未稳定
↓
记录是否充分
↓
是否反复超出审查负荷
↓
才允许讨论下一阶段或分流
```

不能为提高“完成率”或“升级率”降低这一顺序。

## 八、AI长期复盘边界

7天/30天 AI 材料只使用结构化统计和规则结果，默认不带入个人长备注。

AI 不得：

- 诊断疾病；
- 判断气、经络、丹田；
- 判断筑基、入定或其他境界；
- 生成综合修为分；
- 把主动不练写成失败；
- 把超时写成进步；
- 把“可以讨论分流”写成晋级/认证；
- 生成 S2—S4 操作教程。

## 九、V2.3 schema 迁移保护

新增：

`practice-migrations.mjs`

以及：

`33-实践体系/实践记录Schema迁移规范-V1.0.md`

当前没有升级到 schema v2，仍保持 v1。

迁移规则：

- 当前 v1 原样读取；
- 非法 JSON 明确报错，不当作空记录；
- 未来版本拒绝自动降级；
- 缺少 `vN → vN+1` 明确迁移函数时停止；
- 迁移逐版本执行；
- 迁移失败不自动覆盖原 localStorage；
- 迁移后才进入 `normalizeRecord`。

本地读取和 JSON 导入现在都必须走同一个迁移入口。

真正发布 schema v2 前，必须先提供：

```text
migrateV1ToV2
```

及对应测试与字段变更说明。
