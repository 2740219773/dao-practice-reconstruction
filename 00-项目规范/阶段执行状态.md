## 当前主要数据债务

### 1. 图谱节点还缺少统一站内详情

当前图谱节点详情侧栏已经可浏览，但“查看原文”仍主要跳转 GitHub Markdown。

下一步需要建立：

```text
V3 节点 ID
↓
网站统一节点详情路由
↓
正文 + 来源 + 关系 + 争议 + 邻接节点
```

使网站不再长期维持“旧公开知识卡详情”和“V3 图谱源文件”两套入口。

### 2. stage / route 仍是 legacy

`28-修行阶段/` 与 `29-修行路线图/` 尚未进入 V3 严格 `expected_ids`。

需要逐文件审计，尤其避免：

- 把不同内丹传统的修炼阶段合并成一条普遍标准；
- 把知识导航写成必然实践顺序；
- 把“筑基、精气神、性命双修”等后世术语无说明地反读进早期经典。

### 3. 旧网站知识索引与 V3 图谱并存

网站现有 `knowledge.data.ts` 仍服务于早期知识卡公开体系，而 V3 使用 `data/graph.json`。

短期允许并存，但后续需要明确：

- 旧知识卡作为证据/专题内容层；
- V3 作为统一实体与关系导航层；
- 两层通过稳定 ID 映射，而不是永久重复维护两套实体。

### 4. 工程依赖债务

当前 CI 的 `npm ci` 仍报告 4 个依赖风险项（2 moderate / 2 high），需要单独检查依赖链和实际影响，不直接执行无审查自动修复。

GitHub Actions 也提示部分 `actions/*@v4` 的 Node 运行时弃用兼容警告，后续单独评估升级。

## 执行原则

每轮迭代必须进行：

1. 读取仓库实际状态；
2. 内容与数据模型同步修改；
3. 更新机器可读关系；
4. 运行或触发自动质量检查；
5. 修复 CI 暴露的真实数据错误；
6. Git 提交；
7. 可量化进度变化时同步本状态文件；
8. 不为追求指标绕过工作包冻结、安全边界或证据标准。
