
`stage.zhuji` 新增 `source.research.wangmu.foundations`，目前由节点自身 `sources` 声明并通过构建校验；下一次来源注册表版本升级时应纳入全局 canonical registry。

```text

```

## 十、下一批执行顺序

### 第一优先级：旧知识卡 ↔ V3 实体映射

1. 设计稳定 `entity_id` 映射规则；
2. 先映射七核心概念与核心经典；
3. 搜索结果显示“实体总览 / 研究卡”之间的关联入口；
4. 专题页逐步使用 V3 实体 ID，而不是只用标题或旧卡编号。

### 第二优先级：路线模型

1. 设计 `route_kind`；
2. 区分历史路线、实践次第、宗派体系、项目导航；
3. 再审查清修、内丹、养生三条路线是否需要进入机器图谱。

### 第三优先级：工程依赖审计

1. 明确 4 个 npm 风险来自哪些依赖；
2. 判断是否运行时可达；
3. 确认升级兼容性；
4. 再决定升级，不自动强修。

## 执行原则

每轮迭代必须：

1. 读取仓库实际状态；
2. 内容与数据模型同步修改；
3. 历史关系单独核对；
4. 更新机器可读关系；
5. 触发自动质量检查；
6. 修复 CI 暴露的真实问题；
7. Git 提交；
8. 可量化进度变化时同步本状态文件；
9. 不为追求指标绕过工作包冻结、安全边界或证据标准。
