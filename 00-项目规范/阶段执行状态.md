### 八、自动图谱构建

已新增：

`website/scripts/构建知识图谱.mjs`

并接入：

```text
npm run graph
npm run graph:check
npm run build
```

自动检查包括：

- 正式节点 ID 是否唯一；
- V3 `expected_ids` 是否存在对应 Front Matter；
- 节点类型是否合法；
- `school_kind` 是否完整；
- planned 与正式节点是否冲突；
- 来源主 ID 与别名是否重复；
- 关系 ID 是否唯一；
- 关系 source / target 是否存在；
- `source_refs` 是否可解析；
- 对称关系是否重复；
- verification 状态是否合法。

构建成功后生成：

```text
data/nodes.json
data/relations.json
data/graph.json
data/build-report.json
```

其中：

- `nodes.json` 只包含正式节点；
- `relations.json` 保留完整关系与端点状态；
- `graph.json` 只输出双方均为正式节点的可展示图谱；
- planned 节点不会提前进入正式网站图谱。

## 当前主要数据债务

### 1. 三个关键 planned 节点

下一批优先处理：

1. 《抱朴子》：区分内篇/外篇、葛洪作者问题及炼丹/养生材料；
2. 天师道：与后世正一道分层；
3. MEDOBS：确认现代身体观察研究在新版 `research` 层的定位。

### 2. 图谱还未接入前端知识地图

当前 JSON 已能稳定生成，但网站仍主要使用旧的知识卡索引和专题数据。

下一工程阶段需要：

```text
data/graph.json
        ↓
网站知识地图数据层
        ↓
节点详情 / 关系筛选 / 类型筛选
```

### 3. 自动检查尚未覆盖所有旧卡

当前 V3 只严格要求 `expected_ids` 内的正式节点。

目录里其他旧节点仍属于 mixed/legacy 状态。后续应逐步迁移，而不是一次性把全部旧 Markdown 强制纳入严格模式。

### 4. 工程依赖债务

当前 `npm ci` 的依赖审计仍报告若干中高风险依赖项，需要单独评估实际依赖链和升级影响，不能直接无审查执行自动修复。

GitHub Actions 当前也提示部分 `actions/*@v4` 运行时兼容层存在 Node 版本弃用警告，后续应在不影响部署的前提下升级工作流动作版本。

## 执行原则

每轮迭代必须进行：

1. 读取仓库实际状态；
2. 内容与数据模型同步修改；
3. 更新机器可读关系；
4. 运行或触发自动质量检查；
5. 修复 CI 暴露的真实数据错误；
6. Git 提交；
7. 可量化进度变化时同步本状态文件。
