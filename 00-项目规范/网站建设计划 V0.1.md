# 问道志网站建设计划 V0.1

## 一、项目定位

"问道志"是"道修重构计划"的公开展示网站。

网站的核心定位是：

> 将项目知识库中经过筛选的文献、原文、概念、争议、现代研究和风险信息，以普通读者能够理解的方式呈现出来。

网站不是：

* 修炼课程网站；
* 功法教学网站；
* 宗教宣传网站；
* 医疗或养生指导网站；
* AI师父或问答平台；
* 修炼打卡与境界评估平台。

第一阶段的网站定位为：

> **传统道家修炼知识研究工作台的公开预览版。**

---

# 二、网站建设原则

## 1. 仓库是源头，网站是展示层

所有正式知识内容仍然维护在项目知识库中。

网站不得再独立维护另一套重复内容。

整体关系为：

```text
项目知识库
↓
读取知识卡属性
↓
检查网站发布状态
↓
生成网站页面
↓
读者浏览
```

知识卡修改后，网站页面应同步更新。

---

## 2. 不默认公开全部仓库内容

网站只展示以下两类内容：

* 可公开草稿；
* 正式公开。

以下内容不得进入公开网站：

* 不公开；
* 内部预览；
* 已撤回；
* 涉及隐私或真实参与者信息；
* 尚未完成风险判断的具体操作；
* 完整视频、完整课程和大段受版权保护的转录内容。

---

## 3. 原文、解释与假说必须视觉分离

网站不能只在文字中说明"这是项目解释"，还要在页面视觉上区分：

* 原始文献；
* 历代注释；
* 近现代传承解释；
* 现代学术研究；
* 项目解释；
* 项目假说；
* 个人实践记录。

读者应当一眼看出某段内容属于哪一层。

---

## 4. 状态和风险必须置顶

每一张正式知识页面顶部至少显示：

* 知识层级；
* 审核状态；
* 网站发布状态；
* 文献可靠等级；
* 最低解释层级；
* 最高推论层级；
* 反证状态；
* 风险等级；
* 最后修改日期。

原文卡还应显示：

* 引文核对状态；
* 页码状态；
* 使用版本。

---

## 5. 网站优先服务阅读，不追求复杂功能

第一阶段重点解决：

* 内容是否容易找到；
* 卡片关系是否清楚；
* 原文和解释是否容易区分；
* 风险提示是否醒目；
* 手机阅读是否舒适；
* 知识库更新能否同步到网站。

暂不开发注册、评论、打卡、排行榜和个性化推荐。

---

# 三、技术路线

## 1. 网站框架

继续使用 VitePress。

选择理由：

* 与现有 Markdown 知识库兼容；
* 静态网站安全、轻量；
* 构建和部署成本低；
* 支持全文搜索；
* 支持自定义主题和组件；
* 支持构建时读取知识卡；
* 适合文献、知识卡和专题报告。

当前阶段不更换框架。

---

## 2. 技术结构

```text
website/
├─ package.json
├─ package-lock.json
├─ .node-version
├─ docs/
│  ├─ .vitepress/
│  │  ├─ config.ts
│  │  ├─ theme/
│  │  │  ├─ index.ts
│  │  │  ├─ style.css
│  │  │  └─ components/
│  │  └─ data/
│  ├─ project/
│  ├─ library/
│  ├─ originals/
│  ├─ concepts/
│  ├─ disputes/
│  ├─ contemporary/
│  ├─ topics/
│  └─ safety/
└─ scripts/
   ├─ 读取知识卡.ts
   ├─ 校验公开状态.ts
   └─ 生成网站索引.ts
```

---

## 3. 数据处理流程

构建网站时执行以下步骤：

```text
扫描知识卡目录
↓
读取卡片顶部属性
↓
验证字段格式
↓
过滤不允许公开的卡片
↓
按卡片类型分类
↓
生成列表页和详情页
↓
生成搜索索引
↓
生成统计数据
↓
构建网站
```

# 四、网站开发阶段

## 第一阶段：修整网站骨架

目标：让现有演示版成为可长期扩展的基础结构。

主要任务：

1. 调整顶部导航；
2. 增加本地全文搜索；
3. 增加 GitHub 仓库入口；
4. 增加站点图标；
5. 设置网站名称和页面描述；
6. 确定部署路径；
7. 固定 Node.js 版本；
8. 建立自动构建检查；
9. 建立自定义主题目录；
10. 优化移动端基础表现。

建议提交：

```text
feat(网站): 完善基础配置与导航结构
```

---

## 第二阶段：打通知识库和网站

目标：网站不再手工维护文献数量和卡片列表。

主要任务：

1. 建立知识卡读取器；
2. 支持中文属性字段；
3. 读取网站发布状态；
4. 缺少发布状态时默认不公开；
5. 自动生成文献库列表；
6. 自动生成原文库列表；
7. 自动生成概念库列表；
8. 自动生成卡片详情页；
9. 自动统计公开内容数量；
10. 构建时检查无效字段。

建议提交：

```text
feat(网站): 接入知识卡并自动生成公开页面
```

---

## 第三阶段：建立网站公共组件

目标：统一所有知识页面的视觉和信息表达。

需要建立：

* 知识层级标记；
* 审核状态标记；
* 发布状态标记；
* 风险等级标记；
* 证据等级标记；
* 草稿提示条；
* 引文核对提示；
* 原文区块；
* 注释区块；
* 项目解释区块；
* 假说区块；
* 不能直接得出结论区块；
* 来源链条；
* 关联卡片列表；
* 修改记录折叠区。

建议提交：

```text
feat(网站): 建立知识状态与风险展示组件
```

---

## 第四阶段：建立第一批正式内容页

第一批只选择三张样板卡：

1. 《道德经》文献卡；
2. "致虚极，守静笃"原文卡；
3. "静"概念卡。

目的不是增加页面数量，而是验证三种核心页面结构。

验收问题：

* 文献卡是否过长；
* 元数据是否清楚；
* 原文和解释是否分明；
* 表格在手机端是否容易阅读；
* 关联知识卡是否能正常跳转；
* 草稿状态是否足够醒目；
* 风险信息是否容易看到。

建议提交：

```text
feat(网站): 上线第一批三种样板知识页
```

---

## 第五阶段：扩展资料类型

增加以下页面样板：

* 《炁体源流》近现代传承文献页；
* 主张卡页面；
* 争议卡页面；
* 现代研究卡页面；
* 风险资料卡页面；
* 玄丹道阁当代传播资料页。

重点验证：

* 不同知识层级如何区分；
* 传统解释和现代研究是否容易混淆；
* 当代传播观察是否会被误读为推荐；
* 风险内容是否被正确限制。

---

## 第六阶段：上线"静"专题阅读路线

形成第一条完整专题路线：

```text

↓

↓

```

该专题将成为问道志第一版最主要的内容成果。

# 五、部署方案

## 1. 推荐方式

优先选择：

* Cloudflare Pages；
* GitHub Pages；
* 其他支持静态网站的平台。

如果部署在 GitHub Pages 仓库子路径，应设置：

```text
/dao-practice-reconstruction/
```

如果使用独立域名或 Cloudflare Pages 根地址，则使用根路径。

---

## 2. 自动部署流程

每次提交后自动执行：

```text
安装依赖
↓
校验知识卡字段
↓
检查网站发布状态
↓
构建网站
↓
检查无效链接
↓
发布
```

构建失败时禁止发布。

---

## 3. 构建检查规则

以下情况应直接构建失败：

* 正式公开卡没有公开摘要；
* 正式公开卡没有公开注意事项；
* 原文卡缺少使用版本；
* 正式公开原文卡仍未核对且未明确标记草稿；
* 风险二级以上内容缺少风险说明；
* 页面关联了不存在的卡片；
* 存在重复编号；
* 网站发布状态使用了无效值。

# 六、第一版上线内容范围

## 可以上线

* 首页；
* 项目说明；
* 研究方法；
* 当前进度；
* 安全边界；
* 文献库索引；
* 原文库索引；
* 概念库索引；
* 争议与开放问题；
* 当代传播观察；
* 三张样板知识卡；
* "静"专题预告。

## 暂不上线

* 未核对的完整古籍引用；
* 具体呼吸控制步骤；
* 意守和丹田操作教程；
* 实践者私人记录；
* 高风险方法详情；
* 未经许可的完整视频或逐字稿；
* AI自动生成的结论；
* 没有来源的现代科学解释。

# 七、项目资源分配

第一阶段建议保持：

```text
知识内容整理：70%
网站建设：30%
```

网站建设不得影响：

* 原文核对；
* 核心概念卡建立；
* 主张和争议拆解；
* 现代研究检索；
* 安全审查；
* "静"专题完成。

---

# 八、第一版完成标准

满足以下条件时，可以认为网站第一版完成：

* 顶部导航清楚；
* 全文搜索可用；
* 手机端可正常阅读；
* 网站可以自动读取知识卡；
* 公开状态能够控制页面生成；
* 文献、原文、概念三种页面模板完成；
* 草稿和正式公开状态视觉不同；
* 风险内容有明显提示；
* 三张样板卡上线；
* 所有页面均可追溯到知识库源文件；
* 无失效链接；
* 构建和自动部署稳定；
* 网站没有任何具体修炼操作引导。
