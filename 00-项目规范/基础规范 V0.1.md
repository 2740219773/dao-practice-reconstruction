## 2. 统一编号体系

### 2.1 规则

卡片编号格式统一为：

```text
类别前缀-四位流水号
```

| 卡片类别 | 前缀 | 示例 |
| -------- | ---- | ---- |
| 文献卡 | 文献 | 文献-0001 |
| 原文卡 | 原文 | 原文-0001 |
| 概念卡 | 概念 | 概念-0001 |
| 主张卡 | 主张 | 主张-0001 |
| 假说卡 | 假说 | 假说-0001 |
| 争议卡 | 争议 | 争议-0001 |
| 现代研究卡 | 现代研究 | 现代研究-0001 |
| 风险资料卡 | 风险资料 | 风险资料-0001 |
| 决策记录卡 | 决策 | 决策-0001 |

### 2.2 规则说明

- 流水号按类别独立计数，从 0001 开始，**不作废、不复用**；被废弃卡片的编号保留，状态标记为"不予采用"或"已归档"；
- 决策记录卡的日期由 YAML"提出日期"字段记录，不写入编号；
- 文献归属（某原文卡属于哪部文献）通过 YAML"所属文献编号"字段关联，不依赖编号；
- 当某一类别卡片超过 100 张时，可升级为加文献简称的编号（如 `原文-庄子-0001`），升级需先发决策记录卡；
- 其他文件中的 SRC-0001、PAS-0001、CON-QI-001、DEC-2026-001 等编号写法**一律作废**，不进入正式卡片。

## 3. 统一状态名称

### 3.1 卡片状态（9 个，中文）

| 序号 | 状态 | 含义 | 英文对照（仅作技术映射） |
| ---- | ---- | ---- | ------------------------- |
| 1 | 草稿 | 卡片刚建立，内容可能不完整 | draft |
| 2 | 待核对 | 原文、出处、版本或引用尚未完成核对 | source_pending |
| 3 | 来源已核对 | 原始资料已确认，解释仍未审核 | source_verified |
| 4 | 待解释审核 | 原文可靠，翻译、解释或概念关系待审查 | interpretation_pending |
| 5 | 待综合审核 | 内容基本完成，等待整体审核 | review_pending |
| 6 | 已审核 | 符合当前版本规则，可进入正式知识库 | reviewed |
| 7 | 需要修订 | 已发现问题，需要修改 | revision_required |
| 8 | 不予采用 | 存在严重来源、逻辑或安全问题 | rejected |
| 9 | 已归档 | 被新版本取代，保留用于追溯 | archived |

### 3.2 使用规则

- 正式卡片必须填写"当前状态"；
- "已审核"不代表永久正确，只表示符合当前版本标准；
- 状态只允许按流程顺序迁移（草稿 → 待核对 → 来源已核对 → 待解释审核 → 待综合审核 → 已审核），出现问题时转入"需要修订"；严重问题直接"不予采用"；
- 状态迁移必须同步更新"最后修改日期"和"修改记录"。

## 4. 统一 YAML 写法

### 4.1 规则

- **键用英文**（技术名称，供软件、脚本、Obsidian 属性、VitePress 数据页使用）；
- **值用中文**（供人阅读的内容，含状态、类型、类别等枚举）；
- 字母等级（T1—T5、I1—I5、E1—E5、M0—M4、R0—R5、C0—C4、S0—S4）作为正式技术名称保留原样；
- 正文一律中文，不中英混排；软件名（Obsidian、GitHub、Markdown、YAML、VitePress、Zotero）允许出现。

### 4.2 各卡必需字段（第一阶段最小要求）

所有正式卡片必须包含：

```yaml
id:             # 卡片编号，按第 2 节规则
title:          # 卡片标题（概念卡为概念名称）
review_status:  # 状态，按第 3 节 9 个中文状态
text_reliability:     # T1—T5（原文卡、文献卡必填；概念卡如有直接引用必填）
interpretation_level: # I1—I5
counterevidence_status: # C0—C4
risk_level:     # S0—S4
created_at:     # 创建日期 YYYY-MM-DD
updated_at:     # 最后修改日期 YYYY-MM-DD
creator:        # 创建人员
```

涉及现代研究时增加：

```yaml
modern_evidence: # E1—E5 / EX
mapping_strength: # M0—M4
```

涉及实践记录时增加：

```yaml
replication_level: # R0—R5
```

### 4.3 统一示例

```yaml
id: 文献-0001
title: 道德经
text_reliability: T2
interpretation_level: I3
counterevidence_status: C1
risk_level: S0
review_status: 来源已核对
created_at: 2026-08-01
updated_at: 2026-08-01
creator: 项目负责人
```

## 5. 证据等级口径

以《证据等级规范 V0.1》的多维体系为准：

- 文献可靠度：T1—T5；
- 解释层级：I1—I5；
- 现代证据等级：E1—E5、EX；
- 对应关系强度：M0—M4；
- 实践重复度：R0—R5；
- 反证状态：C0—C4；
- 审核状态：见第 3 节（9 个中文状态）；
- 风险等级：S0—S4。

《项目简介》中的 A/B/C/D/E/X 单一等级表**作废**，任何新内容不得使用；修订《项目简介》V0.2 时删除旧表。

## 9. Git 提交规范

- 每完成一组卡片提交一次，不积压；
- 提交信息格式：

```text
docs(类别): 中文摘要
```

示例：

```text
docs(文献卡): 建立道德经文献卡
docs(原文卡): 建立道德经第十六章原文卡
docs(规范): 修订基础规范为 V0.2
```

- 提交历史本身是研究记录，禁止批量覆盖式提交；
- private/ 目录加入 .gitignore，不得提交。
