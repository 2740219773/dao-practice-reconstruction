# 知识分层改为七层、知识卡属性字段中文化、解释等级双字段化

## 1. 原有做法或原有判断

- 项目章程 V0.2 第 7 节规定知识内容分六层：L1 原始文献、L2 历代注释、L3 现代学术研究、L4 项目解释、L5 项目假说、L6 个人实践记录；
- 基础规范 V0.1 第 4.1 节规定 YAML"键用英文、值用中文"，理由是供软件、脚本、Obsidian 属性、VitePress 数据页使用；
- 各知识卡 YAML 使用单一"解释等级"（interpretation_level）字段标注整张卡的解释层级；
- 原文卡的底本可靠等级与引文核对状态合并在"文献可靠等级"（text_reliability）一个字段中表达；
- 现代解释候选（如"默认模式网络活动降低"）直接写入概念卡与原文卡，但没有对应现代研究卡或参考文献；
- 文献卡中的"现代学界一般认为""文本在战国时期逐步形成"等表述没有对应的研究著作、论文或页码；
- README 首页进度停留在步骤 1—3 未完成状态，且核心规则仍写"五层分离"。

## 2. 发现的问题

- 张至顺《炁体源流》、陈撄宁著作等近现代道门传承文献，既不属于古代原典，也不属于现代学术研究，在六层中无处安放；
- "键用英文"与项目"全部使用中文表达"的原则冲突；项目目前没有程序必须依赖这些英文键；
- 一张卡只标一个解释等级会产生误导：卡内同时包含直译（I1 级）与心理学、神经科学候选（I4—I5 级），单一 I1 会让人误以为全部内容都接近字面；
- 底本可靠（T2）与"尚未逐字核对""页码待补"是两件不同的事，合并表达使核对进度不可见；
- 无参考文献支撑的现代机制候选，容易变成"先想到一个脑科学名词，再寻找论文支持"；
- 现代学术观点不可追溯，违背"所有判断可追溯"原则；
- 首页进度过期会让新参与者误判项目状态。

## 3. 可选方案

### 3.1 知识分层：六层改七层

**方案一：在 L2 与 L3 之间插入"近现代传承与实践解释"层，共七层。**

优点：近现代传承文献（《炁体源流》等）有准确位置，且明确属于解释层而非证据层。

问题：涉及章程第 7 节、README、基础规范引用同步修改。

**方案二：维持六层，近现代传承文献归入"历代注释"或"项目解释"层。**

优点：改动最小。

问题：会混淆"古代注释"与"近现代传承实践解释"两类性质不同的材料。

### 3.2 字段语言：英文键改中文键

**方案一：全部改为中文键，一次性迁移全部存量卡片（当前共 13 张）。**

优点：符合"全部使用中文表达"原则；存量少，一次迁移干净，避免新旧写法并存；等级字母（T1/I1 等）作为技术名称保留。

问题：需要同步修改 9 个模板、基础规范、安全边界中的 YAML 写法说明；以后程序读取时需依赖映射表。

**方案二：改为中文键，渐进迁移。**

问题：新旧写法并存期较长，违背决策-0001 消除混用的目标。

**方案三：保留英文键，正式说明技术理由。**

问题：项目目前没有程序依赖英文键，保留缺乏不可替代的理由，且持续与中文表达原则冲突。

### 3.3 解释等级：单字段改双字段

**方案一：YAML 改为"最低解释层级 + 最高推论层级"两个字段。**

优点：一个字段回答"最保守的解释有多近字面"，另一个回答"最远的推论有多远"；正文各节候选继续标注层级；改动小。

**方案二：删除总字段，正文逐条标级。**

优点：粒度最细。

问题：每张卡需要逐条标注全部解释，工作量大，现阶段收益不明显。

**方案三：保持单一字段。**

问题：继续存在误导。

### 3.4 底本与引文核对状态拆分

**方案：保留"文献可靠等级"（底本等级），新增"引文核对状态""页码状态"两个字段。**

底本本身可靠（T2）与"当前录入文字尚未逐字核对"不再混在一个字段。

### 3.5 现代解释候选与参考资料

**方案：**

- 概念卡、原文卡中的现代机制候选降级为"待检索的现代研究方向"，未建立现代研究卡或找到文献前不作为机制候选；
- 新建参考资料编号体系（参考资料-0001 起）与 13-参考资料/ 目录，集中登记作者、题名、出版信息、页码与所支持的判断；
- 文献卡中的现代学术表述逐步补充参考资料编号（列为待办，不回溯编造）。

## 4. 最终决定

1. 知识分层改为七层：L1 原始文献、L2 历代注释、L3 近现代传承与实践解释、L4 现代学术研究、L5 项目解释、L6 项目假说、L7 个人实践记录；
2. 知识卡 YAML 属性字段全部改为中文键、中文值；字母等级（T1—T5、I1—I5、E1—E5、EX、M0—M4、R0—R5、C0—C4、S0—S4）作为正式技术名称保留原样；存量 13 张卡片一次性迁移；
3. 单独建立"中文字段—程序字段映射表"（00-项目规范/字段映射表 V0.1.md），供将来程序读取使用；
4. 解释等级拆为"最低解释层级"与"最高推论层级"两个字段；存量卡迁移时先按原值填入两字段，再按卡内实际内容人工调整最高推论层级；
5. 原文卡新增"引文核对状态""页码状态"字段；文献卡模板新增近现代传承文献专用字段（传承归属、编纂性质、是否包含古籍引文、是否包含编者实践解释、是否包含具体实践方法、是否需要逐段风险审查、是否属于现代学术研究）；
6. 现代机制候选降级为"待检索的现代研究方向"；建立参考资料编号体系（参考资料-0001 起）与 13-参考资料/ 目录，暂不新增卡片类型；
7. 同步修订项目章程（V0.3）、基础规范（V0.2）、九类模板（V0.3）、README 首页；
8. 以《炁体源流》为近现代传承文献试点（文献-0007），先验证新分层与新字段，再决定是否批量加入其他近现代传承文献。

## 5. 决定依据

- 外部审查意见（2026-08-01，对仓库的阶段性审查报告），其中关于分层缺口、字段语言冲突、解释等级误导、引文核对混标、现代解释无文献、参考缺失、首页过期七项问题均已核实属实；
- 决策-0001 第 10 节复审条件："外部评审提出更优方案"时重新讨论本决定——本次调整符合该流程；
- 项目章程第 19 节项目基本声明（允许修改、持续修正）；
- git 历史保留旧版本，保证可追溯。

## 6. 反对意见

- 有意见认为字段中文化后程序读取不便：已通过"字段映射表独立维护"解决，程序映射不进入研究正文；
- 有意见认为近现代传承文献应归入"历代注释"层：未采纳，原因是近现代传承文献常同时包含古籍辑录、宗派解释、口传经验、个人体会与具体实践观点，与古代注释性质不同，混层会再次造成分类混乱；
- 有意见认为七层过于复杂：未采纳，七层是按资料在研究中的作用分类，不增加使用者负担（文献卡只需填对应层的字段）。

## 10. 后续复审条件

出现以下情况时重新讨论本决定：

- 实际使用中中文字段出现明显不便（如工具兼容性问题）；
- 需要建立正式程序化知识库时，映射表需要扩展或修订；
- 近现代传承文献数量增加后需要更细的字段设计；
- 参考资料数量超过 100 条需要重新设计编号方式。
