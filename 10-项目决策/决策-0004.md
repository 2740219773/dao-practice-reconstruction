# 新增"网站发布状态"字段并确立网站公开原则

## 1. 原有做法或原有判断

- 卡片审核状态（9 个中文状态）用于表达内容质量与核对进度，与"是否对外公开"没有对应关系；
- 知识库仓库已推送 GitHub main，仓库本身公开；但"公开网站：问道志"尚未建立（README 定位：第一期末制作最小版）；
- 卡片没有独立的公开控制字段：哪些内容可以上网站、以什么状态展示、如何撤回，均无规则。

## 2. 发现的问题

- 仓库公开与网站公开是两个层面：仓库是源头（允许存在草稿、待核对内容与内部判断），网站是展示层（只应展示经过选择的内容）。没有公开控制字段时，两者边界只能靠人工记忆，容易把未核对内容批量公开；
- 审核状态不能代替公开状态：已审核的卡片可能因风险或隐私原因不公开；内容明确但尚未完成审核的卡片也可能需要提前展示（须明确标识）；把两者混为一个字段，会导致"要么全部公开、要么全部不公开"；
- 网站读者需要知道"看到的这条内容处于什么状态、阅读时要注意什么"，需要面向公众的摘要与注意事项，不能直接复制卡片内部的判断性表述；
- 网站一旦建立，需要一条可追溯的撤回路径：内容下架以卡片字段变更记录留痕，而不是静默删除页面。

## 3. 可选方案

**方案一：知识卡统一新增三字段（网站发布状态、公开摘要、公开注意事项），网站只读取可公开状态的卡片。**（采纳）

优点：公开控制随卡片走，修订、撤回都在卡片上留痕；缺失字段按"不公开"处理，默认安全；网站实现简单——只读字段，不维护独立清单。

问题：需要同步修订基础规范、字段映射表、全部知识卡模板。

**方案二：仅用"当前状态"控制公开（达到"已审核"才公开）。**

问题：审核是质量判断，公开是发布判断，两者合并会导致：需要提前预览的内容无法展示、已审核但不应公开的内容（如高风险实践细节）无法单独控制，反而比现状更混乱。

**方案三：网站手工维护公开清单，卡片不加字段。**

问题：清单与卡片分离，卡片修订后清单容易过期，撤回无留痕，与"所有判断可追溯、可修订"的项目原则冲突。

## 4. 最终决定

1. 所有知识卡（含决策记录卡）统一新增三个字段，默认值"不公开／待补录／待补录"：

```yaml
网站发布状态: 不公开      # 不公开／内部预览／可公开草稿／正式公开／已撤回
公开摘要: 待补录      # 面向公众的公开摘要，正式公开前必须填写
公开注意事项: 待补录      # 面向公众的注意事项，正式公开前必须填写
```

2. "网站发布状态"五种取值：不公开、内部预览、可公开草稿、正式公开、已撤回；状态与"当前状态"（9 个中文审核状态）互相独立，互不替代；
3. 状态流转：不公开 ⇄ 内部预览 → 可公开草稿 → 正式公开；任意状态可转入"已撤回"（网站下架，卡片保留，修改记录留痕）；"已撤回"如需重新公开，从"不公开"重新走流程；
4. 网站（问道志）只读取"可公开草稿"与"正式公开"两种状态的卡片；"内部预览"仅内部预览环境可见；"不公开""已撤回"不在任何公开页面出现；
5. "正式公开"的前提：当前状态达到"已审核"，公开摘要与公开注意事项均已填写，风险等级与卡片发布风险可接受（含 S2 及以上内容的卡片须逐段说明）；"可公开草稿"允许审核未完成，但页面必须显示草稿标识与公开注意事项；
6. 公开摘要：面向公众的独立摘要，不得照抄内部判断性表述；正式公开前必须填写。公开注意事项：面向公众的风险与边界提示（如"本页为研究工作台预览，不构成练习指导"），正式公开前必须填写；
7. 仓库为源头、网站为展示层：网站内容从知识卡读取，卡片修订后网站同步更新；撤回以字段变更+修改记录留痕，不静默删除；
8. 存量卡片暂不强制补填三字段，缺失时按"不公开"处理（默认安全）；卡片下次修订时补填；新建立卡片必须填写；
9. 网站第一版定位为"研究工作台的公开预览版"，不是正式修炼知识平台：不做注册登录、评论区、修炼打卡、练习计时器、境界测试、AI 问答、个性化练习推荐、体感上传、排行榜、今日功法、宣传筑基入门、未核对卡片自动批量公开（12 项不做清单）；
10. 同步修订：基础规范（V0.3：必需字段、目录、模板清单）、字段映射表（V0.3：新增三字段映射）、十个知识卡模板（V0.4：新增三字段）、README（目录、进度、核心规则）；新建 website/ 目录（VitePress 骨架，第一版九个入口：首页、项目说明、研究方法、文献库、原文库、概念库、争议与开放问题、当代传播观察、安全边界）。

## 5. 决定依据

- 项目负责人双轨阶段建议（2026-08-01）：知识整理继续作为主线（约七成精力），同时启动问道志最小网站（约三成精力），用网站反过来检验知识结构；"立即开始一个很小的网站骨架，同时继续完成'静'专题"；
- README 既定定位："公开网站：问道志（第一期末制作最小版）"；
- 决策-0002、决策-0003 建立的字段管理先例：字段变更以决策记录卡确认，映射表同步维护；
- 安全边界 V0.2：中高风险内容只建立研究索引，不转化为公众操作教程——公开原则与之一致。

## 6. 反对意见

- 有意见认为只需用审核状态控制公开：未采纳，审核（质量）与公开（发布）是两个维度，合并后无法表达"已审核但不公开""未审核但需预览"等正常情形；
- 有意见认为公开清单由网站手工维护即可：未采纳，清单与卡片分离会导致过期与撤回无痕，违反可追溯原则；
- 有意见认为网站第一版就可以做成互动平台（打卡、AI 问答等）：未采纳，第一版定位是研究工作台预览，12 项不做清单为硬约束，避免网站拖着项目追求页面数量和视觉效果。

## 9. 生效说明

- 自 2026-08-01 起执行；
- 新建立卡片必须填写三字段（默认不公开）；存量卡片下次修订时补填，缺失按"不公开"处理；

## 10. 后续复审条件

出现以下情况时重新讨论本决定：

- 网站第一版上线后，三字段不足以表达发布需求（如需要按节公开、需要"仅登录可见"等）；
- 出现需要展示 private/ 中内容的需求（本决定默认 private 永不公开）；
- 卡片发布状态与 GitHub 仓库可见性、Pages 部署流程需要联动时；
- 需要将网站部署纳入正式流程（域名、部署账号、更新节奏）时。
